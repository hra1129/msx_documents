# 第1章 本書の目的と解析方法

## 1.1 本書の目的

本書は、MSX turboR（Panasonic FS-A1ST／FS-A1GT）の内蔵ファームウェアを逆アセンブル解析し、特に次の2点を実物のコードから確定させることを目的とする。

- **起動シーケンス** ― 電源投入直後、Z80 と R800 の2つの CPU がどのように協調して起動し、メモリマッパーとスロットが初期化され、DOS や BASIC へ制御が渡るか。
- **S1990 の挙動** ― turboR の心臓部であるエンジンチップ S1990（および T9769C 系の周辺制御）が、CPU 切り替え、DRAM モード、タイマ、ファームウェアスイッチ等をどう制御するか。

あわせて、ユーザからの要望により次の2点も章として収録した。

- **R800 DRAM モードへの BIOS コピーの仕組み**（第5章）― コピーを実行するコードの場所、実行 CPU、コピー元／先、切り替えの方法を逆アセンブルで確定させる。
- **FS-A1GT 内蔵ドライブのドライバ解説**（第9章）― GT のみに存在する SRAM ディスク／ROM ディスク用ドライバの配置と、ROM ディスクの実体・形状を確定させる。
- **スロット 3-3 の全メモリマップ**（第7章）― Panasonic マッパーを通してスロット 3-3 に現れるファームウェア ROM／SRAM／メイン RAM の全体像を図示する。

## 1.2 解析方法と表記

解析は、実機ファームウェア（FS-A1ST／FS-A1GT、各 4MB イメージ）から切り出した ROM 群を静的逆アセンブルして行った。公開資料（MSX Wiki の "R800 Programming"、Grauw の MSX I/O ポート一覧、openMSX のソースコード）と突き合わせ、**食い違う点は実物（逆アセンブル結果）を優先**し、その旨を本文および付録Bに明記した。

本書の表記は次のとおりである。

| 表記 | 意味 |
|---|---|
| 16進数 | 末尾に h を付ける（例： 0416h）。文脈上明らかな場合は省略することがある |
| ブロック | ファームウェアイメージを 8KB 単位で割った番号（0〜511） |
| ページ | CPU アドレス空間の 16KB 単位（ページ0＝0000h〜3FFFh、ページ1＝4000h〜7FFFh、ページ2＝8000h〜BFFFh、ページ3＝C000h〜FFFFh） |
| セグメント | メモリマッパーの 16KB 単位の RAM ブロック |
| スロット表記 | 「スロット 3-1」は基本スロット3の拡張スロット1を指す |

コードの引用は、起動経路の確定に必要な最小限の断片に留めた。ファームウェア ROM イメージそのものやダンプ全体は本書に含めない。

## 1.3 turboR のハードウェア概要

MSX turboR は MSX 規格の最終世代で、Z80 と、その高速な上位互換 CPU である R800 の両方を搭載する。両 CPU はバスを共有し、S1990 が「どちらがバスを使うか」を切り替える。実効クロックは Z80 が 3.58MHz、R800 が約 7.16MHz（内部的にはさらに高速に動作し、メモリアクセス時にウェイトが入る）である。

| 項目 | FS-A1ST | FS-A1GT |
|---|---|---|
| CPU | Z80 + R800（S1990 が切替） | 同左 |
| メイン RAM | 256KB（マッパー、スロット 3-0） | 512KB（マッパー、スロット 3-0） |
| VDP | V9958 | V9958 |
| 音源 | PSG、MSX-MUSIC（YM2413）内蔵 | PSG、MSX-MUSIC 内蔵 |
| MSX-MIDI | なし | 内蔵（I/O E8h〜EFh） |
| PCM | 録音／再生（I/O A4h／A5h） | 同左 |
| ディスク | 3.5インチ FDD ×1、TC8566AF | 同左 |
| 内蔵ドライブ | なし | SRAM ディスク／ROM ディスク（第9章） |
| ファームウェア | 2MB（ブロック 0〜255 を使用） | 4MB（ブロック 0〜511） |

システム制御の中核は S1990 で、I/O ポート E4h／E5h のレジスタ間接アクセスで操作する。詳細は第6章にまとめた。

# 第2章 ファームウェア構成とスロット配置

## 2.1 ファームウェアイメージの構成

FS-A1ST／FS-A1GT のファームウェアは、8KB ブロック単位で管理される大容量 ROM である。ST は 4MB イメージのうち前半 2MB（ブロック 0〜255）だけが使われ、後半は FFh で埋まっている。GT は 4MB 全域（ブロック 0〜511）が対象だが、ブロック 384 以降は全て FFh である。

システム ROM 群は、このイメージの決まったブロック範囲から切り出されて各スロットに配置される。次表は openMSX のマシン定義（Panasonic_FS-A1ST／FS-A1GT）と実イメージの照合で確定した配置である。

| ブロック | サイズ | 配置先 | 内容 |
|---|---|---|---|
| 36〜37 | 16KB | スロット 0-3、4000h〜 | オープニング ROM（2.4 節） |
| 40〜43 | 32KB | スロット 0-0、0000h〜7FFFh | メイン BIOS ＋ MSX-BASIC |
| 48〜55 | 64KB | スロット 3-2、4000h〜7FFFh（バンク切替） | ディスク ROM（DOS カーネル＋ドライバ、第8章） |
| 56〜57 | 16KB | スロット 3-1、0000h〜3FFFh | サブ ROM |
| 58〜61 | 32KB | スロット 3-1、4000h〜BFFFh | 漢字ドライバ ＋ 漢字 BASIC |
| 62〜63 | 16KB | スロット 0-2、4000h〜7FFFh | MSX-MUSIC ROM（FM-BASIC） |
| （GT のみ）256〜319 | 512KB | スロット 3-3 経由でアクセス | ROM ディスクイメージ（第9章） |
| 0〜511 | 最大 4MB | スロット 3-3 全域 | ファームウェア ROM（内蔵ソフト、第7章） |

このほか、漢字フォント ROM（256KB、I/O ポート D8h〜DBh でアクセス）が別チップとして存在する。

## 2.2 スロット配置の全体像

turboR の内蔵デバイスは、基本スロット 0 と 3 に集中している。

| スロット | 内容 |
|---|---|
| 0-0 | メイン BIOS ＋ BASIC（32KB）。DRAM モード対応（第5章） |
| 0-1 | （カートリッジスロット側と共有される領域。本体のみでは未使用） |
| 0-2 | MSX-MUSIC ROM（16KB） |
| 0-3 | オープニング ROM（16KB） |
| 3-0 | メイン RAM（マッパー RAM。ST 256KB／GT 512KB） |
| 3-1 | サブ ROM（16KB）＋ 漢字ドライバ（32KB）。DRAM モード対応（第5章） |
| 3-2 | ディスク ROM（64KB、16KB バンク切替）＋ TC8566AF FDC |
| 3-3 | ファームウェア ROM（Panasonic マッパー）＋ SRAM（ST 16KB／GT 32KB）。第7章 |

カートリッジスロットは基本スロット 1 と 2 で、通常の MSX と同じである。

## 2.3 ST と GT の ROM 差分

両機種のファームウェアをブロック単位で比較した結果は次のとおりである（差分数はバイト単位）。

| ROM | 差分バイト数 | 主な違い |
|---|---|---|
| メイン BIOS | 117 | わずかな差異のみ（起動の骨格は同一） |
| サブ ROM | 8,588 | GT 側に約 +3 バイトのずれを伴う差異が多数 |
| 漢字ドライバ | 0 | 完全に同一 |
| MSX-MUSIC | 11,604 | 大きく異なる |
| オープニング ROM | 14,680 | 大きく異なる |
| ディスク ROM | 27,823 | DOS2 カーネル版数（ST 2.30／GT 2.31）と GT の内蔵ドライブドライバ追加（第9章） |

メイン BIOS の差分が 117 バイトと小さいことから、本書の起動シーケンス解析（第3章〜第5章）は原則として両機種に共通である。機種差が効くのは主にディスク ROM と内蔵ソフトまわりである。

## 2.4 オープニング ROM について

ブロック 36〜37（スロット 0-3）の 16KB は、通常の ROM ヘッダ（"AB"）を持たない。先頭は FFh のパディングで、オフセット 10h 付近に "WSXSEG29P1" のようなセグメント名文字列が見える。これは内蔵ソフト系のセグメントデータの一部と考えられる。起動ロゴ表示との関係を含め、本 ROM の正確な役割分担は本書では確定できなかった（付録B）。

## 2.5 ROM の版数文字列

各 ROM に埋め込まれた版数文字列は次のとおりである。DOS カーネルの版数は第8章で述べる DOS1／DOS2 共存の議論の前提になる。

| ROM | 文字列 |
|---|---|
| ディスク ROM（DOS2 側） | "MSX-DOS kernel version 2.30"（ST）／"2.31"（GT）、Copyright (C) ASCII |
| ディスク ROM（DOS2 側） | "Disk BASIC version 2.01" |
| ディスク ROM（DOS1 側） | "MSX-DOS ver. 2.2 Copyright 1984 by Microsoft"、"Disk BASIC version 1.0" |
| ROM ディスク（GT）収録の MSXDOS2.SYS | "MSX-DOS version 2.31"、Copyright (1990) |

# 第3章 起動シーケンス

## 3.1 概要 ― 2つの CPU が同時に目覚める

turboR の起動が通常の MSX と根本的に違うのは、**電源投入時に Z80 と R800 の両方がアドレス 0 から実行を始める**点である。ハードウェア（S1990）は電源投入直後、Z80 を ROM モードでバスマスタとして選択する。R800 も同時に走り出すが、BIOS の起動コードが両者の役割分担を直ちに決める。片方（Z80）が通常の MSX 初期化を進め、もう片方（R800）は所定の場所で「駐車」して自分の出番を待つ、というのが全体像である。

どちらが起動を主導したかは、I/O ポート F4h（システムフラグレジスタ）の bit5 で判別する。このビットはリセットを跨いで保持され、「R800 の初期化が済んだ」ことを示すフラグとして使われる。S1990 の仕様書（9-1 節）では、この F4h は「リセットステータスレジスタ」と呼ばれ、bit5 はその INIT フラグである。仕様書の起動説明（まず R800 を起動して 1 命令フェッチ後すぐにホールドさせ、Z80 を起動する。Z80 は INIT フラグを 1 にしてから CPU 移行 BIOS を呼び R800 を起動し、R800 は INIT フラグを読んでリセット直後の起動であることを判断して Z80 の制御を引き継ぐ）は、以下の実物解析と一致する。仕様書には実物と同じ構造の「CPU 起動プログラム」（プログラム9-1-1）も掲載されている。

起動コードはメイン BIOS の 126Bh にある（アドレス 0 のジャンプ先）。以下、実物を追う。

## 3.2 最初の分岐 ― F4h の判定（126Bh）

リセット直後のコードは DI の後 126Bh へ跳び、まずポート F4h を読む。

```
        in      a,(0F4h)        ; システムフラグを読む
        bit     7,a             ; ウォームブートか？
        jr      nz,WARM
        bit     5,a             ; R800 初期化済みか？
        jr      nz,PARK         ; 済み → R800 側の経路
        ; --- Z80 によるコールドスタート ---
        or      20h             ; bit5 を立てる
        out     (0F4h),a
        ...
WARM:   ...
PARK:   im      1
        xor     a
        jp      0489h           ; CHGCPU の中ほどへ
```

分岐は3通りある。

| 条件 | 意味 | 行き先 |
|---|---|---|
| bit7 = 1 | ウォームブート（リセットボタン等。bit7 はソフトブートを示す） | CHGCPU（046Ah）を A＝80h で呼び、Z80 モードへ戻してから 1299h へ |
| bit7 = 0、bit5 = 1 | R800 の初期化は済んでいる。**このコードを実行しているのは R800** | 129Ch： IM 1 の後、A＝0 で CHGCPU の中間入口 0489h へ跳び、自らを駐車させる |
| bit7 = 0、bit5 = 0 | 完全なコールドスタート。**実行しているのは Z80** | bit5 を立てて R800 起動手続きへ |

つまり同じコードを両 CPU が実行し、F4h bit5 の「先着フラグ」で役割が決まる。先に bit5 を見た Z80 が初期化を担当し、後から来た R800 は bit5 が立っているのを見て駐車経路に入る。

## 3.3 Z80 による R800 の起動

コールドスタートの Z80 側は、R800 を起こす前に turboR 固有デバイスの最低限の初期化を行う。

1. F4h に bit5 を立てて書き戻す（「R800 初期化中／済み」の宣言）。
2. PCM の初期化（ST で確認）： ポート A4h へ 80h、ポート A5h へ 3 を書く。
3. ポート A7h（ポーズ／LED）へ 02h を書く。A7h のシャドウ変数（ワークエリア FCB1h）の初期値でもある（第4章）。
4. S1990 のレジスタ 6 を選択し（E4h へ 6）、データポート E5h へ OTIR で 2 バイト（40h、60h）を書く。

手順 4 が R800 の起動である。レジスタ 6 の意味は bit5＝CPU 選択（0＝R800、1＝Z80）、bit6＝ROM モード（1＝ROM）なので、40h は「R800・ROM モード」を意味する。書き込みの瞬間に Z80 は停止し、R800 がバスマスタになる。R800 はアドレス 0 から（実際には駐車中の状態から）実行を始め、3.2 節のコードで bit5 が立っていることを検出して 0489h へ跳び、CHGCPU の機構を使って自分を Z80 モードの影に駐車させる。制御は Z80 に戻り、Z80 は 1299h から通常の INIT（0416h）へ進む。

なお、手順 4 で 2 バイト目（60h）が書かれる理由は第4章で論じる。仕様書により、レジスタポインタは進まず、2 バイト目は同一レジスタへの「2 回目の設定データ」であると判明した（4.2.1 節）。

## 3.4 INIT 前半 ― マッパーと RAM の初期化（0416h）

INIT（0416h）は MSX 標準の初期化だが、冒頭で turboR のマッパー初期値が設定される。

```
0416h:  xor     a
        out     (0FFh),a        ; ページ3 のセグメント = 0
        inc     a
        out     (0FEh),a        ; ページ2 のセグメント = 1
        inc     a
        out     (0FDh),a        ; ページ1 のセグメント = 2
        inc     a
        out     (0FCh),a        ; ページ0 のセグメント = 3
```

続いてポート BBh へ 8、ABh へ 82h（エンジン系の制御）、基本スロットを全ページ 0 にし、PPI（AAh）へ 50h を書く。次に、アドレス FFFFh（拡張スロットレジスタ）への書込み／読出しで各基本スロットの拡張有無と RAM の所在を調べ、見つけた RAM ページの最上位に SP を設定して、ページ1のコード 7B61h へ跳ぶ。

## 3.5 INIT 後半 ― ワークエリアとスロットスキャン（7B61h〜）

7B61h では次の処理が進む。

1. ワークエリア F380h〜FBF7h（約 3.1KB）を 0 で初期化する。
2. SLTATR（FCC4h〜）等のスロット属性表を初期化し、各ページの拡張スロットレジスタ値を FCC5h／FCC7h に記録する。
3. IM 1 を設定し、7C76h へ進む。ここから先で VDP／PSG 等のデバイス初期化、フックの初期化、**スロットスキャン**（各 ROM のヘッダを確認し、INIT エントリを呼ぶ）が行われる。ディスク ROM の INIT（403Ch）もこの段階で呼ばれ、DOS カーネルの初期化とドライブ登録が行われる（第8章）。
4. スロットスキャンの後、7D14h で **CALL 0162h** を実行する。これが R800 DRAM モード用の BIOS コピー（第5章）である。コピー後も起動は Z80・ROM モードのまま進む。コピーは「将来 CHGCPU で DRAM モードへ移ったとき」に備えた準備である。
5. 以後、制御は BASIC の起動経路（411Fh 方面）へ移り、Disk BASIC の初期化を経て、ブート可能なディスク（GT では内蔵 ROM ディスクを含む）があれば DOS が起動し、なければ BASIC が起動する。DOS2 環境では、DOS カーネルが起動時に CPU モードを R800 DRAM モードへ切り替えるのが既定である（CPU モードと DOS の版は独立しており、DOS1 でも R800 モードは使える）。

## 3.6 起動シーケンスのまとめ

| 順序 | 実行 CPU | 処理 |
|---|---|---|
| 1 | Z80 と R800（両方） | アドレス 0 から実行開始。ハードウェアは Z80・ROM モードを選択 |
| 2 | Z80 | F4h bit5 を立て、PCM／A7h を初期化。S1990 reg6 へ 40h を書き R800 を起動 |
| 3 | R800 | F4h bit5 を見て駐車経路（0489h）へ入り、自らを停止させる |
| 4 | Z80 | INIT（0416h）： マッパー初期値、RAM 探索、SP 設定 |
| 5 | Z80 | 7B61h〜： ワークエリア初期化、スロットスキャン、各 ROM の INIT |
| 6 | Z80 | CALL 0162h： BIOS／サブ ROM 等を RAM 末尾セグメントへコピー（第5章） |
| 7 | Z80 | BASIC 起動経路へ。DOS 起動時はカーネルが R800 DRAM モードへ切替 |

# 第4章 CPU 切り替え ― CHGCPU／GETCPU

## 4.1 公開エントリ

turboR のメイン BIOS は、CPU モードを操作する2つの公開エントリを持つ。どちらも MSX 標準のジャンプテーブルに追加された turboR 専用エントリである。

| エントリ | 実体 | 機能 |
|---|---|---|
| 0180h（CHGCPU） | 046Ah | CPU モードを変更する |
| 0183h（GETCPU） | 04D2h | 現在の CPU モードを取得する |

モード番号の約束は次のとおりである。

| モード | CPU | 実行場所 |
|---|---|---|
| 0 | Z80 | ROM |
| 1 | R800 | ROM |
| 2 | R800 | DRAM（RAM 上のコピー、第5章） |

Z80 の DRAM モード（レジスタ 6 の値 20h）はハードウェア上存在するが、CHGCPU ではサポートされない。

## 4.2 CHGCPU の実物解析（046Ah）

入力は A レジスタで、bit7 は「LED を更新するか」のフラグ、bit1〜0 がモード番号である。モードが 3 以上なら何もせずに戻る。

処理の骨格は次のとおりである。

1. **全レジスタの退避** ― 主レジスタ一式（AF／BC／DE／HL／IX／IY）に加え、影レジスタ一式と I レジスタまで全てスタックへ退避し、SP をワークエリア **FFFDh** に保存する。Z80 と R800 はレジスタを共有しないため、切り替えを跨いで状態を運ぶ手段はメモリ（スタックと FFFDh）しかない。
2. **A7h シャドウの更新** ― ポート A7h（ポーズ／LED）のシャドウ変数はワークエリア **FCB1h** にある。入力から次の規則でビットを決め、FCB1h に保存して A7h へ出力する。
   - bit1： モード 0（Z80）のとき 1、それ以外は 0。
   - bit7（R800 LED）： bit7 フラグが立っていて、かつモードが 0 でないとき 1。それ以外は 0。つまり LED の点灯は純粋にソフトウェア制御であり、実際の CPU モードをハードウェアが表示するものではない。
3. **S1990 レジスタ 6 の書き換え** ― モード表（04E3h、モード×2 バイト）から値を取り、E4h でレジスタ 6 を選択して E5h へ OTIR で書く。モード表の内容は次のとおりである。

| モード | 書き込むバイト列 | レジスタ 6 の値の意味 |
|---|---|---|
| 0（Z80） | 60h, 60h | bit5=1（Z80）、bit6=1（ROM） |
| 1（R800 ROM） | 40h, 60h | bit5=0（R800）、bit6=1（ROM） |
| 2（R800 DRAM） | 00h, 60h | bit5=0（R800）、bit6=0（DRAM） |

書くバイト数 B は「現在のレジスタ 6 の bit5 が 1（＝現在 Z80）なら 2、そうでなければ 1」と決められる。切り替えが発効すると、相手側 CPU が OTIR の直後（04B9h）から実行を再開する。
4. **復帰** ― 04B9h 以降は DI、SP を FFFDh から復元し、退避した全レジスタを逆順に戻して EI、RET する。この後半部分は「切り替え先の CPU」が実行する前提で書かれており、どちらの CPU が入ってきても同じコードで復帰できる。

起動コード（第3章）が CHGCPU の中間入口 **0489h** へ直接跳ぶのは、この「退避済み」の状態から処理を始めるためである。R800 の駐車も、ウォームブート時の Z80 への復帰も、同じ機構に相乗りしている。

### 4.2.1 2 バイト目は何処へ行くか

モード表の 2 バイト目が常に 60h で、現在 Z80 のときだけ 2 バイト書かれる理由は、公開資料では説明されていなかった。しかし S1990 の仕様書により、この論点は決着した。

仕様書には、CHGCPU と同名の「CPU 制御移行 BIOS 例」（プログラム9-2-1）が掲載されており、実物とバイト単位で同じアルゴリズムである。A7h シャドウの操作（SLA C、RES／SET 1,A、RES／SET 7,A）、レジスタ 6 を選択して現在の値を読み bit5 で書く回数を決める手順、モード表の値（60h,60h／40h,60h／00h,60h）まで全て一致する。そして 2 バイト目のコメントは「Z80の2回目の設定データ」と明記されている。つまり 2 バイト目は、同じレジスタ設定操作における **2 回目の設定データ** として設計されたものである。

宛先を決めるのは、仕様書 12-1 節のアクセス定義である。E4h のアドレスは下位 4 ビットで、アクセスは「番号を E4h に設定してから E5h を読み書きする」方式と定義され、**ポインタの自動インクリメントは仕様書のどこにも記載されていない**。掲載プログラム自体も、E4h へのアドレス設定を 1 回だけ行い、続けて IN（読み）と OTIR（書き）を実行している。読みや書きでポインタが進む仕様では、この公式例自体が誤ったレジスタを指してしまう。openMSX の S1990 実装が自動インクリメントをモデル化していないことも、この読みと一致する。

結論として、2 バイト目は **レジスタ 6 への再書き込み** である。モード 1／2 で 60h（Z80・ROM の値）を書き直すことが切り替えを妨げないのは、1 バイト目の書き込み時点で仕様書 9-2-1 の切り替えシーケンス（システム IC が Z80 へバスリクエストを出し、バスが解放されるのを待って R800 を起動する）が既に始まっており、再書き込みがモード変更として実効を持たないため、と解釈するのが仕様書の記述と最も整合する。モード 0 では書き直される値が同じ 60h なので、そのまま無害である。なお「レジスタポインタ自動インクリメント説」に立つ場合に想定されたレジスタ 7 への書き込みは、以上の結論により CHGCPU では行われない。レジスタ 7 自体の機能は、本書が参照した仕様書写真の範囲（12-1 節の続きは未撮影）では定義を確認できていない。

なお、仕様書の掲載プログラムには LD A,03H と印字されているが、そのコメントは「レジスタアドレス06hを設定」であり、実物（04A9h）も LD A,6 である。03H は仕様書側の誤記と判断できる（付録B）。

## 4.3 GETCPU の実物解析（04D2h）

GETCPU はレジスタ 6 を読み、bit6／bit5 をモード番号へデコードして A に返す。実物は値を 2 回左シフトしてフラグだけで判定する簡潔なコードである。

| レジスタ 6 の bit6,5 | 戻り値 | 意味 |
|---|---|---|
| 11（60h） | 0 | Z80 |
| 10（40h） | 1 | R800 ROM |
| 00（00h） | 2 | R800 DRAM |
| 01（20h） | 0 | Z80 DRAM（ハードウェア上は存在するが、Z80 と報告される） |

## 4.4 ポート A7h と FCB1h

ポート A7h は読み書きで意味が異なる。

| 方向 | ビット | 意味 |
|---|---|---|
| 読み | bit0 | ポーズスイッチの状態（R800 モードでのみ有効とされる。Z80 の WAIT に接続） |
| 書き | bit7 | R800 LED（turbo LED）の点灯制御 |
| 書き | bit1 | BIOS は Z80 モードで 1、R800 モードで 0 に設定する。openMSX はこのビットを「ハードウェアポーズの有効化」としてモデル化している |
| 書き | bit0 | ポーズ LED の点灯制御 |

書き込み値の影は FCB1h に保持され、BIOS 以外が A7h を読んでも書き込み値を読み戻すことはできない（読みはスイッチ状態である）ため、A7h を操作するプログラムは FCB1h を経由するのが作法である。

# 第5章 R800 DRAM モードと BIOS コピー

## 5.1 DRAM モードとは

R800 は、内蔵キャッシュを持たない代わりに「ROM の内容を RAM（DRAM）へコピーして、そこから実行する」ことで高速化するモードを持つ。これが **R800 DRAM モード**（モード 2）である。ROM は読み出しにウェイトがかかるが、コピー先のマッパー RAM は高速にアクセスできるため、BIOS や BASIC の実行が速くなる。

重要な事実は2つある。

- **コピーは S1990 が行うのではない。** S1990 はメモリ転送の機能を持たず、行うのは「ROM 読み出しを DRAM 側へ向け替える」切り替えだけである。コピー自体は CPU が通常のメモリコピー命令で実行する。
- **コピー先はマッパー RAM の最後の 4 セグメント**である。この領域は DOS2 が既定で予約し、通常のプログラムからは「存在しないセグメント」として見える（読み出すと FFh が返るように扱われ、マッパー容量がその分小さく見える）。

本章では、逆アセンブルで確定したコピーの実体を、メイン BIOS 分とサブ ROM 分に分けて示す。

## 5.2 メイン BIOS のコピー ― 03ACh（公開入口 0162h）

メイン BIOS 32KB のコピーは、メイン BIOS 自身の **03ACh** にあるルーチンが行う。ジャンプテーブルの **0162h** がこのルーチンへの公開入口で、起動時は INIT の後半（7D14h）から呼ばれる。実行するのは **Z80** で、この時点ではまだ ROM モードのままである。

処理の中心は次の部分である（抜粋）。

```
03D8h:  ld      a,0FCh
        out     (0FEh),a        ; ページ2 のセグメント = FCh
        ld      hl,0000h        ; コピー元 = BIOS 前半（0000h〜3FFFh）
        ld      de,8000h        ; コピー先 = ページ2 の窓
        ld      bc,4000h        ; 16KB
        ldir
        ld      a,0FDh
        out     (0FEh),a        ; ページ2 のセグメント = FDh
        ld      hl,4000h        ; コピー元 = BIOS 後半（4000h〜7FFFh）
        ld      de,8000h
        ld      bc,4000h
        ldir
        ld      a,01h
        out     (0FEh),a        ; ページ2 のセグメントを 1 に戻す
```

工夫は「コピー先をページ2（8000h〜BFFFh）の窓越しに書く」点にある。コピー元であるページ0／ページ1の ROM は最後まで見えたままで、実行中のコード自身もページ0にあって影響を受けない。マッパーレジスタ（FEh）で窓の向こうのセグメントを差し替えながら、16KB ずつ2回転送する。

コピー先セグメントに FCh／FDh という大きな番号が使われるのは、マッパーのセグメント選択が実装ビット数で折り返すことを利用した「最後のセグメント群」を指す常套手段である。

| 機種 | 実装セグメント数 | FCh の実体 | FDh の実体 |
|---|---|---|---|
| FS-A1ST（256KB） | 16 | セグメント 12 | セグメント 13 |
| FS-A1GT（512KB） | 32 | セグメント 28 | セグメント 29 |

つまりコピー先はどちらの機種でも「最後から 4 つ目と 3 つ目」のセグメントである。ルーチンの前段では、セグメント数検出用のサブルーチン（7E1Ah）を繰り返し呼んで B レジスタに値を組み立て、ワークエリア FCFDh へ記録している。これはマッパー容量の判定を兼ねた処理とみられる。ルーチンは最後に 1472h へ跳び、起動処理の続き（ワークエリア初期化の後半）へ合流する。

## 5.3 サブ ROM と漢字ドライバのコピー ― サブ ROM 3F1Ch

DRAM モードで向け替えの対象になるのはメイン BIOS だけではない。サブ ROM（16KB）と漢字ドライバの前半（16KB）もコピーが必要で、これは **サブ ROM 自身の 3F1Ch** にあるルーチンが担う。起動時、サブ ROM 内の初期化ルーチン（0476h）から呼ばれる。

処理は次のとおりである（要約）。

1. ページ2 のセグメントを **FEh** にし、CPU アドレス 0000h〜3FFFh（この時点でページ0に見えているサブ ROM 自身）16KB をページ2 の窓（8000h〜）へ LDIR でコピーする。
2. 基本スロットレジスタ（A8h）のページ1／ページ3 分をスロット 3 にし、拡張スロットレジスタ（FFFFh）のページ1 分を 1 にして、**ページ1 にスロット 3-1（漢字ドライバ）を割り当てる**。
3. ページ2 のセグメントを **FFh** に変え、ページ1（4000h〜7FFFh＝漢字ドライバの前半 16KB）をページ2 の窓へ 16KB コピーする。
4. ページ2 のセグメントを 1 に戻し、スロットレジスタを復元して戻る。

FEh／FFh の実体は 5.2 節と同じ折り返しで、ST ではセグメント 14／15、GT では 30／31、すなわち「最後の 2 セグメント」である。4 セグメントの割り当ては次のように揃う。

| セグメント（末尾から） | 内容 | コピー担当 |
|---|---|---|
| 最後から 4 つ目（FCh） | メイン BIOS 前半 16KB | メイン BIOS 03ACh |
| 最後から 3 つ目（FDh） | メイン BIOS 後半 16KB | メイン BIOS 03ACh |
| 最後から 2 つ目（FEh） | サブ ROM 16KB | サブ ROM 3F1Ch |
| 最後（FFh） | 漢字ドライバ前半 16KB | サブ ROM 3F1Ch |

サブ ROM 側ルーチンが「自分の居るページ0から自分自身をコピーする」形になっている点が興味深い。コピー先はページ2 の窓の向こうであり、実行中のページ0 は切り替えないため、この自己コピーは安全に成立する。ページ1 の差し替えは漢字ドライバを読むためだけに行われ、コピー後に復元される。

なお、漢字ドライバの後半 16KB（ブロック 60〜61）は DRAM モードの向け替え対象ではない。DRAM モードでも後半は ROM から読まれる。

## 5.4 切り替えの瞬間 ― ハードウェア側の向け替え

コピーが済んだ状態で CHGCPU（第4章）でモード 2 を選ぶと、S1990 レジスタ 6 の bit6 が 0 になり、ハードウェアが ROM 読み出しを DRAM 側へ向け替える。向け替えの単位はファームウェアの 8KB ブロックで、対象は次の範囲である（openMSX の PanasonicMemory 実装と実 ROM のコピー範囲が一致することから確定）。

| ファームウェアブロック | 本来の内容 | DRAM モード時の読み出し先 |
|---|---|---|
| 40〜43（28h〜2Bh） | メイン BIOS ＋ BASIC | RAM 末尾 64KB の前半 32KB（セグメント FCh／FDh のコピー） |
| 56〜59（38h〜3Bh） | サブ ROM ＋ 漢字ドライバ前半 | RAM 末尾 64KB の後半 32KB（セグメント FEh／FFh のコピー） |

この向け替えはスロット 0-0／3-1 としての読み出しだけでなく、スロット 3-3 の Panasonic マッパー経由で同じブロックを読む場合にも効く（第7章）。また、コピー領域（RAM 末尾 64KB）は、スロット 3-3 の窓経由の書き込みから保護される。誤って BIOS コピーを書き潰す事故を防ぐためのものと考えられる。

## 5.5 逆方向と CHGCPU／GETCPU との関係

DRAM モードから戻る操作は、コピーを伴わない。CHGCPU でモード 1（R800 ROM）またはモード 0（Z80）を選べば、レジスタ 6 の bit6 が 1 に戻り、その瞬間から読み出しは ROM へ戻る。RAM 上のコピーは残っているが参照されなくなるだけであり、再度モード 2 へ移れば（コピーが壊されていなければ）そのまま使える。コピーを作り直す必要があるのは、電源投入後まだ一度も 0162h が実行されていない場合と、コピー領域を他の用途で上書きした場合だけである。

関係を整理すると次のようになる。

| 操作 | 実体 | コピーの要否 |
|---|---|---|
| 起動時の準備 | BIOS の INIT が 0162h（03ACh）を呼び、サブ ROM 初期化が 3F1Ch を呼ぶ | この時点で 64KB 分のコピーが作られる |
| DRAM モードへ | CHGCPU（0180h）モード 2 → レジスタ 6 ＝ 00h | 不要（済んでいる） |
| ROM モードへ | CHGCPU モード 0／1 → レジスタ 6 の bit6 ＝ 1 | 不要 |
| 現在モードの確認 | GETCPU（0183h）がレジスタ 6 をデコード | ― |

## 5.6 注意点

- コピー先の 4 セグメントは、DOS2 のメモリ管理では「予約済み」として扱われる。DOS1 環境やベアメタルなプログラムがマッパーを直接操作すると、この領域を通常セグメントと誤認して壊すことがある。
- コピーは起動時に一度だけ作られる。カートリッジソフトが RAM 末尾を書き換える設計の場合、DRAM モードへ移る前に 0162h を呼び直すのが安全である。
- Z80 の DRAM モード（レジスタ 6 ＝ 20h）はハードウェア的には存在するが、BIOS は経路を用意していない（GETCPU は Z80 と報告する。第4章）。

# 第6章 S1990 と周辺デバイス

## 6.1 S1990 へのアクセス方法

S1990 は turboR のエンジンチップで、CPU バスの調停、CPU 選択、メモリマッピングの一部、システムタイマなどを担う。アクセスは I/O ポート経由のレジスタ間接方式である。

| ポート | 方向 | 機能 |
|---|---|---|
| E4h | 書き／読み | レジスタ選択（選択したレジスタ番号を読み戻せる） |
| E5h | 書き／読み | 選択中レジスタへのデータアクセス |
| E6h | 読み | システムタイマ下位 8 ビット。書くとタイマがリセットされる |
| E7h | 読み | システムタイマ上位 8 ビット |

S1990 の仕様書（12-1 節）によれば、E4h のレジスタアドレスは下位 4 ビット（R3〜R0）で、上位ビットは 0 である。アクセスの手順は「E4h にレジスタ番号を書き込んでから E5h をアクセスする」というもので、**E5h へのアクセスでレジスタポインタが自動的に進むという仕様は、仕様書のどこにも記載されていない**（この点は第4章の CHGCPU 解析で長く未確定だった論点で、4.2.1 節で決着した）。レジスタ番号は 0〜15 が基本だが、デバッガーサポート機能（6.11 節）にはそれを超える番号のレジスタ群が仕様書に現れる。

## 6.2 レジスタマップ（確定分）

S1990 の仕様書（12-1 節、12-3 節）で定義が確認できたレジスタは次のとおりである。従来 Grauw の資料で知られていたのは 5／6／14／15 の一部だけだったが、仕様書により 4 の「未サポート」、5 の全ビット、デバッガーサポート用のレジスタ群まで確定した。

| レジスタ | 方向 | 機能 |
|---|---|---|
| 4 | 読み | システムステータス入力ポート。S1990 ではサポートされず、全ビット未定義 |
| 5 | 読み | システムスイッチ入力ポート。bit6＝SSW2（内蔵ソフトスイッチ）、bit5＝SSW1（DOS 選択スイッチ）、bit4＝SSW0（システムモードスイッチ）。詳細は 6.4 節 |
| 6 | 書き／読み | システムセッティングレジスタ。SYS1（bit6）／SYS0（bit5）で CPU と動作環境を選択する。ほかにソフトウェアリセット用の RST ビットがある（ビット位置は本書が参照した仕様書写真の範囲外） |
| 0Dh | 書き／読み | デバッグモニター用スロットレジスタ。bit1＝DST3、bit0＝DST0（6.5 節） |
| 0Eh／0Fh | 書き／読み | NMI リターンアドレスレジスタ（RA15〜RA0）（6.5 節） |
| 10h〜13h／20h〜23h | 書き | アドレスコンパレータ 1／2（6.11 節） |

レジスタ 6 以外への書き込みは、BIOS の通常経路では行われない。openMSX の実装でも、書き込み可能なのは実質レジスタ 6 のみとしてモデル化され、それ以外のレジスタの読みは FFh を返す（レジスタ 13〜15 を除く）。

レジスタ 6 のビット配置は次のとおりである。

```
レジスタ 6（システムセッティングレジスタ）
  bit7   bit6   bit5   bit4 〜 bit0
  ────   ────   ────   ────────────────
   ―     SYS1   SYS0    （RST ビットを含む。
         （ROM   （CPU    位置は写真範囲外）
          モード） 選択）
```

| bit6（ROM モード） | bit5（CPU） | 状態 | CHGCPU のモード |
|---|---|---|---|
| 1 | 1 | Z80・ROM | 0 |
| 1 | 0 | R800・ROM | 1 |
| 0 | 0 | R800・DRAM | 2 |
| 0 | 1 | Z80・DRAM | （BIOS 非サポート） |

仕様書では SYS1／SYS0 の組をモード名で呼び、（1,1）＝MSX2+ モード、（1,0）＝MSX turbo モード、（0,0）＝MSX superturbo モードとしている（仕様書 9-2 節）。superturbo へ移るには「システムソフトウェアを DRAM 上に前もってコピーしておく必要がある」と明記されており、第5章のコピーがその前提であることも裏付けられた。

電源投入直後の値は 60h（Z80・ROM）で、ハードウェアが自動的にこの状態を選ぶ。

## 6.3 システムタイマ（E6h／E7h）

E6h／E7h は 16 ビットのフリーカウンタで、255,682Hz でカウントアップする（1 カウント ≈ 3.911μs）。E6h への書き込みでカウンタは 0 にリセットされる。BIOS はこのタイマを通常の時間管理には使っておらず（時刻はクロック IC が担う）、主に精密な時間計測を要するプログラムのための資源である。

## 6.4 システムスイッチ入力ポート（レジスタ 5）

レジスタ 5 は、本体のスイッチ入力を読み出すポートである。仕様書（図12-1-3）では 3 つのスイッチが定義されている。従来の公開資料（Grauw）では bit6 のみが「ファームウェアスイッチ」として知られていたが、正式には次のとおりである。

| ビット | 名称 | 意味 |
|---|---|---|
| bit6 | SSW2 | 内蔵ソフトスイッチ。0＝内蔵ソフト OFF、1＝ON |
| bit5 | SSW1 | DOS 選択スイッチ。0＝DOS2、1＝DOS1 |
| bit4 | SSW0 | システムモードスイッチ。0＝MSX turbo、1＝MSX2+ |

BIOS／DOS のコードは SSW2（bit6）を随所で参照する。代表例が GT の内蔵ドライブドライバで、レジスタ 5 の bit6 とキー入力の組み合わせで内蔵ドライブの有効化を判定している（第9章）。またメイン BIOS の初期化でも、内蔵ソフトを起動するか否かの判断に使われる。

## 6.5 デバッガーサポートレジスタ（0Dh〜0Fh）と読み値

レジスタ 0Dh〜0Fh は、デバッガーサポート機能（6.11 節）のためのレジスタである（仕様書 12-3 節）。

| レジスタ | 名称 | 内容 |
|---|---|---|
| 0Dh | デバッグモニター用スロットレジスタ | bit1＝DST3（デバッグモニターワークエリア制御）、bit0＝DST0（デバッグモニタープログラム制御）。いずれも 0＝OFF、1＝ON |
| 0Eh | NMI リターンアドレス（上位） | RA15〜RA8 |
| 0Fh | NMI リターンアドレス（下位） | RA7〜RA0 |

デバッグモニターが NMI で起動し CPU が 0066h をアクセスすると、DST0 と DST3 がともに 1 になり、page0（0000h〜3FFFh）は強制的に slot02 へ、page3（C000h〜FFFFh）も強制的に slot02 へ切り替えられる。デバッグモニターのプログラムは slot02 の 0000h〜3FFFh、ワーク用 RAM は slot02 の C000h〜FFFEh に置かれる（物理的には ROM4／RAM4 にマッピングされる）。両ビットはデバッグモニター側から自由に書き換えでき、0 に戻すと起動前のスロット環境に戻る。

NMI リターンアドレスレジスタは、デバッグモードへ移行する直前にメモリへ書き込まれた最後の 2 バイトのデータを保持する。NMI の受け付けで CPU がスタックへ書き込むリターンアドレスがそのまま捕捉されるわけで、Grauw の資料がレジスタ 14／15 を「最後にメモリへ書かれたバイト（とその1つ前）」と説明していたのは、このレジスタのことだったと分かる。値は読み書き可能で、I/O ポート E3h へ任意のデータを書き込んだ後に RETN 命令を実行すると、2 バイトのリターンアドレスフェッチの際にこのレジスタの内容が CPU へ渡される。書き換えてから復帰すれば、異なるアドレスへ戻すこともできる。

これにより、長く未確定だった「レジスタ 13 の読み値」にも決着がついた。レジスタ 0Dh の読み値は DST3／DST0 の状態そのものであり、固定値ではない。通常動作時は両ビットとも 0、デバッグモニター動作中は両ビットとも 1 になる。openMSX が返す固定値 03h は「モニター動作中の状態」に相当するもので、通常時の読み値ではない（openMSX のソース上も TODO と明記された暫定値である）。レジスタ 0Eh／0Fh についても同様で、読み値は直前の NMI で捕捉されたリターンアドレスに依存し、固定値 2Fh／8Bh は実機の保証値ではない。

## 6.6 PCM（A4h／A5h）― S1990 の外側

PCM の録音／再生は S1990 ではなく独立したデバイスで、ポート A4h（データ）と A5h（制御）を使う。起動時、BIOS は A4h へ 80h、A5h へ 3 を書いて初期化する（第3章）。サンプリングは 8 ビットで、再生専用に使う限りは単純な仕様である。録音側はマイク入力を持つ実機でのみ意味を持つ。

## 6.7 ポーズと LED（A7h）

ポート A7h の詳細は第4章（4.4 節）にまとめた。要点は、読み＝ポーズスイッチ、書き＝ LED とポーズ機能の制御で、書き込み値の影が FCB1h に置かれることである。ポーズスイッチは Z80 の WAIT 信号に接続され、R800 モードでのみ有効とされる。

## 6.8 システムフラグ（F4h）

ポート F4h は MSX2+ 世代の「初期化ステータスレジスタ」を引き継ぎ、turboR では次のビットが起動制御に使われる。値はリセットを跨いで保持される。

| ビット | 意味 |
|---|---|
| bit7 | ソフトブート（1＝ウォームブート。起動ロゴ表示を省略する側の条件） |
| bit5 | R800 起動済み（1＝R800 の初期化が完了している。第3章の役割分担に使用。仕様書ではリセットステータスレジスタの INIT フラグと呼ばれる） |

## 6.9 MSX-MIDI（GT のみ、E8h〜EFh）

FS-A1GT は MSX-MIDI を内蔵し、I/O ポート E8h〜EFh を使う。S1990 とは別デバイスである。存在の有無はメイン ROM の 002Eh の bit0 で示される（MSX のシステム変数としての約束）。ST には搭載されない。BIOS 起動時の扱いは、スロットスキャンと F5h（内蔵 I/O 制御）による有効化の枠組みに乗る。

## 6.10 ウェイトとリフレッシュについて

R800 のメモリアクセスには、アクセス先に応じてウェイトが挿入される。特に、ROM 領域やカートリッジへのアクセスは DRAM より低速で、これが DRAM モード（第5章）の存在理由である。仕様書（8-5 節）には、MSX turbo モード時のウェイト数が明記されている。

| アクセス先 | ウェイト |
|---|---|
| DRAM | 0（ページブレーク発生時は 1） |
| ROM | 2 または 1 |
| SRAM | 2 |
| カートリッジバス（I/O を除く） | 3〜5 |
| I/O デバイス | 5〜6（漢字 ROM は 2 または 1） |

これらのウェイトは、ZWAIT 信号の R800 タイミングへの変換、Z80 バスタイミングシミュレータ（仕様書 8-2 節）が生成するウェイト、アクセスガード回路によるウェイト等の合算である。シミュレータは、R800 が周辺デバイス（スロットバス、V9958、S1985 等）へアクセスする際に Z80 のメモリサイクル／I/O サイクルの信号タイミングを再現するもので、外部スロットや FDC インターフェースへは 3 サイクル（バスクロックとアクセスのタイミングがずれたときは 4 サイクル）、I/O デバイスへは 5 サイクル（同 6 サイクル）のウェイトを入れ、連続アクセス時にはサイクルタイム確保のため 2 サイクル余分にウェイトを入れる。V9958 に対しては、レジスタアクセスに続いて 8μs 以内に次のアクセスがあった場合、アクセスサイクルが 8μs 以上になるようウェイトを入れて開始を遅らせる。ディスク ROM の FDC レジスタ（7FF2h〜）へのアクセスで、R800 モード時に追加ウェイトが入ることが openMSX の実装から読み取れるのも、この枠組みに沿う。なお MSX2+ モード（Z80 動作時）には本 IC はウェイト制御を行わない（M1 サイクルの 1 ウェイトは MSX2 エンジンチップ側の担当）。

DRAM のリフレッシュ制御を S1990 のレジスタで直接操作する経路は、BIOS からも仕様書からも確認できなかった。仕様書の起動シーケンスの注記によれば、電源投入後の DRAM 初期化に要するポーズ期間と 8 サイクルのダミーサイクルは、リセット期間（16ms 以上）でポーズが保証され、リセット解除後は Z80 がオペコードフェッチのたびにリフレッシュを実行し、命令実行前に DRAM をアクセスしないことで保証される、という設計である。

## 6.11 デバッガーサポート機能（アドレスコンパレータ）

S1990 には、デバッガーを効率よく動作させるためのハードウェアが内蔵されている（仕様書 12-3 節）。中核は **アドレスコンパレータ** で、R800 のアドレスを監視し、ある値になったときに NMI 割り込みを発生させてデバッガーを起動する。ただしアドレスコンパレータは、**リセット時に A8 信号が pull down されているときのみ使用可能**で、アドレスコンパレータとは別に、メモリ空間の FFFFh 番地へのアクセスに対する NMI 発生回路も備える。コンパレータは R800 動作時のみ有効である。

コンパレータは 22 ビットのものが 2 組内蔵され、I/O の E4h〜E5h 番地のシステムセッティングレジスタ内に置かれる（レジスタ番号は仕様書に R#10h〜13h／R#20h〜23h と記される。12-1 節の E4h アドレスフィールドが下位 4 ビットであることとの関係は、本書が参照した仕様書写真の範囲では説明されていない）。

| レジスタ | 内容 |
|---|---|
| R#10h／R#20h | コンパレータアドレス CA7〜CA0 |
| R#11h／R#21h | CA15〜CA8 |
| R#12h／R#22h | CA21〜CA16（上位 2 ビットは未使用） |
| R#13h／R#23h | 制御。bit7＝FFFF（FFFFh アクセスで割り込み発生、1 でイネーブル）、bit5＝RD、bit4＝WR、bit3＝ADMD（0＝メモリアクセス、1＝I/O アクセス）、bit2〜0＝CMD2〜CMD0 |

CMD0〜CMD2 はマスク指定で、CMD0 が 0 のとき CA7〜CA0 は無効、CMD1 が 0 のとき CA12〜CA8 は無効、CMD2 が 0 のとき CA21〜CA13 は無効、という具合に数ビット毎に比較をマスクできる。また ADMD により、そのアドレスがメモリアクセス時のものか I/O アクセス時のものかを判断できる（I/O の場合は CMD2 と CMD1 を 0 に、CMD0 を 1 に、ADMD を 1 にすることで正常な I/O アドレスの比較ができる）。コンパレータ制御回路は、アドレスが一致したら R800 の NMI 信号検出に要する時間だけ自動的にウェイト（1 ウェイト）を発生する。割り込みが発生した後は RD ビットと WR ビットはクリアされる。RD／WR の組み合わせは、00＝コンパレータインヒビット（初期値）、01＝データライトで割り込み、10＝データリードで割り込み、11＝データリード／ライトで割り込み、を意味する。

ブレークキーもサポートされる。アドレスコンパレータがイネーブルになっている状態では、PSKEY 端子はブレークキーの入力端子として使われ、端子が low になると（ポーズキーが押されると）NMI 割り込みが発生し、同時にデバッグモニターが起動される。この状態では PSKEY 端子はポーズキーとしても有効になるので、I/O A7h 番地のポーズイネーブルビットを禁止しておく必要がある。デバッグモニターが動作中は NMI 割り込みは起動されない。コンパレータが禁止されているときは、PSKEY 端子は CPU に対してバスリクエストを発生したりして CPU のプログラム実行を中断するために使用される。

デバッグモニターの起動シーケンスは次のとおりである。NMI を受け付けた CPU が 0066h 番地をアクセスすると NMI 処理用のスロットマップに変更され（6.5 節の DST ビット）、スタックポインタと全レジスタ、スロットレジスタ等を退避してデバッグモニターが起動する。復帰時はレジスタ類とスタックポインタを復帰し、OUT (E3h),A の後に RETN を実行して、リターンアドレスを CPU へ渡しスロット環境を復帰する。

# 第7章 スロット 3-3 ― Panasonic マッパーと全メモリマップ

## 7.1 スロット 3-3 の役割

スロット 3-3 には、ファームウェア ROM の全体とバッテリバックアップ付き SRAM が、**Panasonic マッパー**と呼ばれる独自のバンク切り替え機構越しに配置されている。内蔵ソフト（ワープロや MSX-JE 等）はこのスロットから実行され、GT の内蔵ドライブ（第9章）もこの窓越しにファームウェアへアクセスする。

Panasonic マッパーの特徴は、バンク番号が **9 ビット**あり、ファームウェア ROM だけでなく **メイン RAM そのものまでバンク空間に現れる**ことである。つまりスロット 3-3 は「本体の全メモリへの窓口」になっている。

## 7.2 バンク空間マップ

バンクは 8KB 単位で、番号は 000h〜1FFh の 512 通り。割り当ては次のとおりである（openMSX の RomPanasonic 実装の定数 SRAM_BASE＝80h、RAM_BASE＝180h と、実機ファームウェアの構成から確定）。

```
図7.1 スロット 3-3 のバンク空間（8KB バンク、9 ビット）

バンク番号   内容                                   ST       GT
──────────  ─────────────────────────────────────  ───────  ───────

```

注意すべきは「影」の存在である。

- バンク 080h〜083h は SRAM が優先されるため、**ファームウェア ROM のブロック 128〜131 はこの窓からは読めない**。
- バンク 180h 以降はメイン RAM が優先されるため、**ROM ブロック 384 以降はこの窓からは読めない**（GT の実イメージでもブロック 384 以降は全て FFh で、実害はない）。
- ST のファームウェアイメージは 2MB（ブロック 0〜255）のため、バンク 100h 以降の ROM 読みはイメージの折り返しになる。

メイン RAM が現れる範囲は、マッパー RAM の 8KB ブロック単位である。マッパーの 16KB セグメントとの対応は、セグメント n ＝ RAM ブロック 2n（前半 8KB）と 2n＋1（後半 8KB）である。第5章の DRAM コピーの置き場所（RAM 末尾 64KB）は、この窓では RAM ブロックの末尾 8 個、すなわち ST ではバンク 198h〜19Fh、GT ではバンク 1B8h〜1BFh に相当する。

スロット 3-3 が選択されたページでは、64KB 全域が 8 つの 8KB リージョンに分かれ、リージョンごとに独立したバンクを割り当てられる。

## 7.4 バンク切り替えレジスタ

| アドレス | 方向 | 機能 |
|---|---|---|
| 6000h〜7FEFh | 書き | バンク番号の下位 8 ビット。対象リージョンはアドレスの bit12〜10 で決まる（図7.2） |
| 7FF8h | 書き | バンク番号の第 9 ビットを全リージョン分まとめて指定（bit n ＝ リージョン n の第 9 ビット） |
| 7FF9h | 書き | 制御レジスタ（下表） |
| 7FF0h〜7FF7h | 読み | 制御 bit2 が 1 のとき、各リージョンのバンク番号下位 8 ビットを読み戻せる |
| 7FF8h | 読み | 制御 bit4 が 1 のとき、各リージョンの第 9 ビットを読み戻せる |
| 7FF9h | 読み | 制御 bit3 が 1 のとき、制御レジスタ自身を読み戻せる |

| 制御ビット | 意味 |
|---|---|
| bit2 | 7FF0h〜7FF7h のバンク読み戻しを有効化 |
| bit3 | 7FF9h の制御読み戻しを有効化 |
| bit4 | 7FF8h の第 9 ビット読み戻しを有効化 |

リセット時は制御レジスタは 0、全リージョンのバンクは 0 に戻る。

この方式のため、バンク番号が 256 以上の対象（GT の ROM ディスクはバンク 100h〜、メイン RAM は 180h〜）を扱うには、7FF8h による第 9 ビットの設定が必須である。第9章のドライバは、まさにこの手順（7000h へ下位 8 ビット、7FF8h へ第 9 ビット、7FF9h へ制御値）でリージョン 4（8000h〜9FFFh）にファームウェアを引き込んでいる。

## 7.5 マッパーレジスタ（FCh〜FFh）との関係

混同しやすいが、スロット 3-3 の Panasonic マッパーと、スロット 3-0 のメイン RAM を切り替える標準メモリマッパー（I/O ポート FCh〜FFh）は別物である。

| 機構 | 切り替え対象 | 粒度 | 操作方法 |
|---|---|---|---|
| 標準メモリマッパー | スロット 3-0 の RAM を CPU の各ページへ | 16KB セグメント | I/O ポート FCh〜FFh への書き込み |
| Panasonic マッパー | スロット 3-3 の中身（ROM／SRAM／RAM）をスロット内の各リージョンへ | 8KB バンク | スロット 3-3 選択中のメモリ書き込み（6000h〜7FF9h） |

両者の関係は「二重の窓」である。たとえば DRAM コピーのセグメント（標準マッパーで数えた RAM 末尾）は、Panasonic マッパー経由では RAM ブロックとして別の番号で現れる。S1990 はこのどちらにも直接関与しない。S1990 の役割は CPU 選択と、第5章で述べた「ROM 読み出しの DRAM への向け替え」であり、向け替えはブロック番号のレベルで両方の窓に効く。

## 7.6 DRAM モードとの相互作用

第5章の向け替え（ブロック 40〜43 と 56〜59）は、PanasonicMemory 相当のハードウェア機能として実装されており、スロット 3-3 から同じブロックを読む場合にも適用される。すなわち DRAM モード中は、スロット 3-3 の窓からブロック 40 を読んでも、返るのは ROM の内容ではなく RAM 上のコピーである。逆に、コピー領域への書き込みはこの窓からも抑止される。

# 第8章 ディスク ROM と DOS カーネル

## 8.1 ディスク ROM の配置とバンク切り替え

ディスク ROM はスロット 3-2 にあり、64KB の ROM が **16KB の窓（4000h〜7FFFh）** にバンク切り替えで現れる。FDC は TC8566AF で、レジスタはメモリマップドである。

| アドレス | 機能 |
|---|---|
| 7FF0h（書き） | ROM バンク選択。値の下位 2 ビットで 4 ページ（各 16KB）を選択 |
| 7FF2h | FDC 制御レジスタ 0 |
| 7FF3h | FDC 制御レジスタ 1 |
| 7FF5h | FDC データポート |

現在のバンク番号は、各ページ自身の 40FFh に「自分のページ番号」が格納されることで読み取れる（どのページが見えていても、そのページの番号が読める）。カーネル内のページ跨ぎ呼び出しは、ページ0 の 7FD0h にあるバンク切り替えトランポリン（(7FF0h) へ値を書く小さなルーチン）と、40FFh の影を使って行われる。

なお、FDC レジスタへのアクセスには R800 モード時に 1 サイクルの追加ウェイトが入る（openMSX の TurboRFDC 実装で確認）。高速な R800 に対して FDC の応答を保証するためのハードウェア上の配慮である。

## 8.2 ページ構成 ― DOS2 と DOS1 の共存

64KB の内訳は次のとおりである。各ページは先頭に "AB" ヘッダを持ち、独立した ROM として振る舞える形になっている。

| ページ | 内容 | ヘッダの INIT／STATEMENT |
|---|---|---|
| ページ 0 | DOS2 カーネル前半、Disk BASIC 2.01 の一部、ドライバ群（FDC ドライバ、GT では内蔵ドライブドライバも） | INIT＝403Ch、STATEMENT＝575Ch |
| ページ 1 | DOS2 カーネル後半 | INIT＝403Ch、STATEMENT＝575Ch |
| ページ 2 | DOS2 カーネル／Disk BASIC 2.01 の残り | INIT＝403Ch、STATEMENT＝575Ch |
| ページ 3 | **DOS1 カーネル**（"MSX-DOS ver. 2.2 Copyright 1984 by Microsoft"）と Disk BASIC 1.0 | INIT＝576Fh、STATEMENT＝6576h |

これが「turboR では DOS1／DOS2 カーネルが同一スロットにバンク切り替えで共存する」という構造の実体である。turboR より前の MSX では、DOS2 を使うには DOS2 カーネル ROM カートリッジが別スロットに必要だった。turboR は両カーネルを 1 つのディスク ROM に収め、起動時にどちらを使うかを選ぶ。

版数は、DOS2 カーネルが ST で 2.30、GT で 2.31。DOS1 側は両機種とも共通の構成である。

## 8.3 ドライバの公開エントリ（ページ 0）

ページ 0 の 4010h 以降には、ディスクドライバ文書（本シリーズ既刊）で言う「公開エントリーテーブル」が標準の並びで置かれている。

| アドレス | エントリ | GT 実体 |
|---|---|---|
| 4010h | DSKIO | JP 7459h |
| 4013h | DSKCHG | JP 779Dh |
| 4016h | GETDPB | JP 77F9h |
| 4019h | CHOICE | JP 781Ah |
| 401Ch | DSKFMT | JP 7C52h |
| 401Fh | MTROFF | JP 7713h |
| 4022h 以降 | DOS2 拡張エントリ群 | カーネル側の登録処理へ |

INIT（403Ch）はページ0 の 7FD0h トランポリンでバンクを 0 に戻してから 47D6h へ進み、マスター／スレーブ判定と DRVTBL へのドライブ登録を行う。これは既刊「MSX ディスクドライバ文書」で解析した DOS1／DOS2 カートリッジと同型の枠組みである。DOS2 の下では、カーネルが実際に使う公開エントリは DSKIO と MTROFF が中心で、DPB はブートセクタの BPB 解釈で構築される、という既刊の知見は turboR の内蔵 DOS2 でも基本的にそのまま当てはまる（第9章の ROM ディスクの BPB の件は例外的な論点として付録Bに記す）。

## 8.4 DOS の起動

起動の流れ（第3章）の中で、ディスク ROM の INIT がドライブを登録し、Disk BASIC の初期化がブート可能な媒体を探す。DOS2 で起動する場合、カーネルはページ 0〜2 の側を使い、DOS1 モードではページ 3 のカーネルに切り替わる。どちらの場合も CPU モードの選択（Z80／R800 ROM／R800 DRAM）はカーネルの版とは独立で、DOS2 の既定は R800 DRAM モードである。

GT では、フロッピーディスクに加えて内蔵 ROM ディスクがブート候補になる。次章でそのドライバを詳しく見る。

# 第9章 FS-A1GT 内蔵ドライブ ― SRAM ディスク／ROM ディスク

## 9.1 概要

FS-A1GT の DOS2（カーネル 2.31）には、フロッピーディスクに加えて、本体ファームウェアを媒体とする内蔵ドライブのドライバが組み込まれている。対象の媒体は2種類ある。

- **ROM ディスク** ― ファームウェア ROM 内に用意された FAT12 イメージ。そのまま DOS2 のブートドライブになり得る、読み取り専用のドライブ。
- **SRAM ディスク** ― スロット 3-3 のバッテリバックアップ SRAM を媒体とする、読み書き可能な小容量ドライブ。

FS-A1ST のディスク ROM（カーネル 2.30）にはこのドライバは存在しない。ST／GT のディスク ROM 差分（27,823 バイト）の主要因のひとつである。本章では GT のディスク ROM ページ 0 の逆アセンブルから確定したドライバの構造を示す。

## 9.2 ドライバの配置

ドライバの本体は、ディスク ROM ページ 0 の **70C7h〜7458h** にある。FDC ドライバの公開エントリ（DSKIO＝7459h 等）の直前に置かれ、ページ 0 のドライバ群の一部として組み込まれている。主要な構成要素は次のとおりである。

| アドレス | 内容 |
|---|---|
| 70C7h | ファームウェア窓の割り当てヘルパ。ENASLT（0024h）でページ2 にスロット 3-3 を割り当てる |
| 70E1h | スロット割り当ての復元ヘルパ（F343h の影を使う） |
| 70F6h | Panasonic マッパーのプログラミング。制御（7FF9h）へ 1Ch、リージョン4のバンク下位（7000h）と第9ビット（7FF8h）を書く |
| 7118h | ドライブの初期化・媒体検査まわり |
| 729Ah | 媒体パラメータテーブル（9.4 節） |
| 72C9h | 有効化判定。S1990 レジスタ 5 の bit6（ファームウェアスイッチ）とキー入力（SNSMAT）を見る |
| 72DBh〜 | 媒体の署名検査。8000h に引き込んだファームウェア先頭と "option ROM"（10 バイト）を照合する |
| 732Fh／7390h | 73A8h の文字列群を参照する初期化表示まわり |
| 73A8h | 文字列群： "SRAMdisk by JS"、"option ROM"、"patch ROM" |

ドライバ内部では、ドライブごとのワークエリア（IX 相対 +1Ah〜+1Dh）に、媒体種別フラグ（+1Ah）と Panasonic マッパーのバンク基底（+1Bh〜+1Dh）が保持される。

## 9.3 ファームウェアへのアクセス方法

媒体の読み出しは、第7章の Panasonic マッパーを通じて行われる。手順は次のとおりである。

1. ENASLT でページ2（8000h〜BFFFh）にスロット 3-3 を割り当てる。
2. Panasonic マッパーの制御レジスタ（7FF9h）へ 1Ch を書き、バンク読み戻しを有効化する。
3. リージョン4（8000h〜9FFFh）のバンクを、7000h（下位 8 ビット）と 7FF8h（第 9 ビット）で設定する。ROM ディスクの基底はバンク 100h（ファームウェアブロック 256）である。
4. 論理セクタ番号からバンク内オフセットを計算し（8KB バンク ＝ 512 バイト×16 セクタ）、8000h の窓から読み出す。
5. 終了時にスロット割り当てを復元する。

媒体が SRAM の場合は、同じ窓の仕組みでバンク 80h 台（SRAM 領域）を対象にし、書き込みも行われる。

有効化の判定（72C9h）が興味深い。このルーチンは S1990 レジスタ 5 を読み、bit6（ファームウェアスイッチ）が立っていなければ即座に戻る。立っていれば SNSMAT（0141h）でキーボード行を読み、特定のキー状態を検査する。つまり内蔵ドライブは「ファームウェアスイッチの位置＋起動時のキー操作」で有効化される設計で、常時見えるドライブではない。

また 72DBh 以降の初期化では、引き込んだファームウェアの先頭 10 バイトを "option ROM" という署名文字列と照合し、内蔵ソフト（オプション ROM）領域の有無を媒体テーブル（RAM 8200h〜に構築される）へ反映する。"option ROM"、"patch ROM" という文字列群は、このファームウェア領域の種別表示に使われるものと考えられる。

## 9.4 媒体パラメータテーブル（729Ah）

729Ah には、8 バイトの媒体名 "SRAMdisk" に続けて、BPB（BIOS Parameter Block）形式のパラメータが置かれている。解読した値は次のとおりである。

| 項目 | 値 |
|---|---|
| セクタ長 | 512 バイト |
| クラスタ | 1 セクタ |
| 予約セクタ | 1 |
| FAT 数 | 1 |
| ルートディレクトリエントリ数 | 16 |
| 総セクタ数 | 34（17,408 バイト） |
| メディア ID | FFh |
| FAT セクタ数 | 1 |

総容量 17,408 バイトは、スロット 3-3 の SRAM（GT 32KB／ST 16KB）のうちドライブとして使う範囲を示す値とみられる。名称が "SRAMdisk" であることからも、このテーブルは SRAM ディスク側のものと判断する。DOS2 は DPB を BPB 解釈で構築する方式（既刊「MSX ディスクドライバ文書」第5章）であり、このテーブルはその入力になっていると考えられる。

## 9.5 ROM ディスクの実体

ROM ディスクのイメージは、GT ファームウェアの **ブロック 256（ファイルオフセット 200000h）から 512KB**（ブロック 256〜319）に置かれた FAT12 イメージである。ST のファームウェアにはこの領域自体が存在しない（ST はブロック 255 まで）。

ブートセクタの内容は次のとおりである。

| 項目 | 値 |
|---|---|
| 先頭バイト列 | EB FE 90（自分自身へのジャンプ。通常のブートセクタ実行は想定されていない形） |
| OEM 名 | "ROM disk" |
| セクタ長 | 512 バイト |
| クラスタ | 1 セクタ |
| 予約セクタ | 1 |
| FAT 数 | 1 |
| ルートディレクトリエントリ数 | 32（BPB 上の値） |
| 総セクタ数 | 2,050（BPB 上の値、約 1MB） |
| メディア ID | FFh |
| FAT セクタ数 | 6（BPB 上の値） |
| ボリュームラベル | "VOL_ID"、ボリューム名 "ROM disk" |

ブートセクタの +30h 以降には通常の DOS2 ブートコード（MSXDOS2.SYS を読み込む処理と "Boot error / Press any key for retry" のメッセージ）が存在する。

しかし、イメージの**物理配置**を実測すると、BPB の値とは一致しない。

| 項目 | BPB の値 | 実測した物理配置 |
|---|---|---|
| FAT セクタ数 | 6 | 3（セクタ 1〜3） |
| ルートディレクトリ | 32 エントリ（2 セクタ） | 1 セクタ（セクタ 4、16 エントリ分） |
| データ領域の開始 | セクタ 9 | セクタ 5 |
| 総容量 | 2,050 セクタ（約 1MB） | イメージ実体は 512KB（データの実使用はセクタ約 1,017 まで） |

FAT の先頭は FF FF FF で始まり、収録ファイルのクラスタチェーン（MSXDOS2.SYS はクラスタ 2〜11 の連続チェーン）が正しく辿れることから、ドライバ／カーネルはこの物理配置で読み出している。BPB の各値が実配置のほぼ 2 倍になっている点は、9.4 節のドライバ側パラメータと併せ、**DOS2 がこのドライブについてはブートセクタの BPB ではなくドライバ側の形状情報で DPB を構築している**可能性を示す。詳細は付録Bに課題として記す。

## 9.6 収録ファイル

ルートディレクトリの内容は次のとおりである（実測）。

| ファイル名 | サイズ | 先頭クラスタ | 備考 |
|---|---|---|---|
| （ボリュームラベル） "ROM disk" | ― | ― | 属性 28h |
| MSXDOS2.SYS | 4,870 バイト | 2 | 先頭は JP 命令と "MSX-DOS version 2.31" のバナー。ROM 常駐カーネルを起動するための小さなローダとみられる |
| COMMAND2.COM | 15,708 バイト | 12 | DOS2 のコマンドインタプリタ |
| AUTOEXEC.BAT | 289 バイト | 43 | 起動時バッチ |
| REBOOT.BAT | 462 バイト | 44 | 再起動用バッチ |

MSXDOS2.SYS が通常のディスク版（数十KB）に比べて小さいのは、DOS2 カーネル本体がディスク ROM に常駐しており、このファイルはその起動を担うローダだからと考えられる。これにより GT は、フロッピーディスクなしで DOS2 を ROM から直接起動できる。

## 9.7 読み取り専用ドライブとしての特徴

- ROM ディスクへの書き込みは媒体自体が ROM であるため成立しない。ドライバの書き込み経路は SRAM 媒体に対してのみ意味を持ち、ROM 媒体ではエラーとなる（通常のディスクドライバの「書き込み禁止メディア」と同じ扱い）。
- メディア交換の概念がない。DSKCHG は常に「交換されていない」を返せばよく、GETDPB は固定の形状を返せばよい。固定媒体である分、FDC ドライバのようなモーター制御（MTROFF）やリトライ処理も不要である。
- アクセスは Panasonic マッパーの窓越しのメモリコピーであり、シーク時間がない。反面、アクセスのたびにページ2 のスロット割り当てとバンク設定を行うため、割り込みや他スロットとの競合には通常のドライバ以上に注意が払われている（70C7h のヘルパが F343h の影を使って割り当てを保存／復元する）。

## 9.8 ST にドライバが無いことの確認

ST のディスク ROM（カーネル 2.30）には、"SRAMdisk" 等の文字列は存在せず、ページ 0 の 70C7h〜7458h に相当するドライバブロックも無い。ページ 0 の公開エントリテーブル（4010h〜）自体は ST／GT で同じ並びだが、GT ではこの追加ドライバが組み込まれ、カーネルも 2.31 に上がっている。ST のファームウェアには ROM ディスクイメージの置き場所（ブロック 256 以降）自体がないため、ドライバだけを移植しても動作しない。

# 付録B 公開資料との相違点・未確定事項

本書の解析で、公開資料と実物（逆アセンブル）の間に見つかった相違点、および現時点で確定できなかった事項をまとめる。いずれも本文では実物を優先して記述した。なお初版の発行後、ユーザから S1990 システム IC 仕様書の撮影写真（抜粋 24 枚）が提供され、一部の未確定事項が決着した。その結果は B.3 に分けて記す。

## B.1 確定した相違点

| # | 論点 | 公開資料の記述 | 実物 |
|---|---|---|---|
| 1 | DRAM コピーの担当 | MSX Wiki はサブ ROM 3F1Ch のルーチンを紹介するが、コピー全体がこの 1 ルーチンであるかのように読める | コピーは2か所に分かれる。メイン BIOS 32KB はメイン BIOS 03ACh（入口 0162h）が、サブ ROM＋漢字ドライバ前半はサブ ROM 3F1Ch が担当する |
| 2 | 「最後の 4 ページ」の実体 | 「マッパーの最後の 4 ページにコピーされる」という記述 | セグメント番号 FCh〜FFh を書き、ST（16 セグメント）では 12〜15、GT（32 セグメント）では 28〜31 に折り返ることで「最後の 4 つ」を実現している |
| 3 | GETCPU の Z80 DRAM 扱い | レジスタ 6 の値 20h（Z80・DRAM）の存在は知られている | GETCPU（04D2h）は 20h を「0＝Z80」と報告する。BIOS 経由では Z80 DRAM モードは区別できない |
| 4 | A7h の bit1 | MSX Wiki のポート一覧は bit0（ポーズ LED）と bit7（R800 LED）のみを記す | CHGCPU は bit1 を「Z80 モードで 1、R800 モードで 0」に必ず設定する。openMSX はこのビットをハードウェアポーズ有効化として実装している |
| 5 | ROM ディスクの BPB | ブートセクタの BPB は総セクタ 2,050、FAT 6 セクタ、ルート 32 エントリと記載 | 物理配置は FAT 3 セクタ、ルート 1 セクタ、データ開始セクタ 5、実体 512KB。BPB の値は物理配置と一致しない（9.5 節） |
| 6 | 仕様書の CHGCPU 掲載プログラム | S1990 仕様書プログラム9-2-1(b) は LD A,03H と印字 | そのコメントは「レジスタアドレス06hを設定」で、実物（04A9h）も LD A,6。03H は仕様書側の誤記と判断できる（4.2.1 節） |
| 7 | マッパー初期値 | 仕様書プログラム9-1-1（CPU 起動プログラム）は FCh←0、FDh←1、FEh←2、FFh←3 の順に書き、最終状態はページ0＝セグメント0〜ページ3＝セグメント3 | 実物の INIT（0416h）は FFh←0 から逆順に書き、最終状態はページ0＝セグメント3、ページ1＝2、ページ2＝1、ページ3＝0。掲載プログラムは汎用の例であり、量産 BIOS とは最終状態が異なる（3.4 節） |

## B.3 S1990 仕様書（写真）で決着した事項

ユーザ提供の S1990 システム IC 仕様書の撮影写真（第3・5・7・8・9・11・12章の抜粋）により、次が決着した。

| # | 事項 | 決着内容 |
|---|---|---|
| 1 | CHGCPU の OTIR 2 バイト目の宛先 | **レジスタポインタは進まない**。仕様書 12-1 節のアクセス定義（E4h に番号を設定してから E5h をアクセス）に自動インクリメントの記載はなく、仕様書の公式プログラム例（9-2-1）も、アドレス設定 1 回の後に IN と OTIR を続け、2 バイト目を「Z80の2回目の設定データ」と明記する。2 バイト目はレジスタ 6 への再書き込みで、切り替え開始後は実効を持たない（4.2.1 節） |
| 2 | S1990 レジスタ 13（0Dh）の読み値 | レジスタ 0Dh は**デバッグモニター用スロットレジスタ**（DST3／DST0）。読み値は状態依存で、通常動作時は 0、デバッグモニター動作中は両ビットが 1 になる。openMSX の固定値 03h はモニター動作中の状態に相当し、通常時の読み値ではない（6.5 節） |
| 3 | レジスタ 14／15（0Eh／0Fh）の正体 | **NMI リターンアドレスレジスタ**。デバッグモード移行直前にメモリへ書かれた最後の 2 バイト（＝NMI でスタックへ書かれたリターンアドレス）を保持する。Grauw の「最後に書かれたバイト」という説明と同一のレジスタだった（6.5 節） |
| 4 | レジスタ 5 の全ビット | SSW2（bit6）＝内蔵ソフトスイッチ、SSW1（bit5）＝DOS 選択スイッチ、SSW0（bit4）＝システムモードスイッチ、と仕様書図12-1-3 で確定。レジスタ 4 は「S1990 ではサポートされない」ことも明記された（6.4 節） |
| 5 | 起動シーケンスの裏付け | 仕様書 9-1 節とプログラム9-1-1 が、実物の起動コード（F4h bit5＝INIT フラグによる役割分担、R800 の駐車、CHGCPU による起動）と一致することを確認した（第3章） |
| 6 | ウェイト数の裏付け | 仕様書 8-5 節に turbo モード時のウェイト表（DRAM 0、ROM 1〜2、SRAM 2、カートリッジ 3〜5、I/O 5〜6）が明記され、6.10 節に反映した |
