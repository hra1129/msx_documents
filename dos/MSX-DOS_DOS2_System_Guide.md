# 第1章 概要

## 1.1 本書の目的

本書は、MSX のディスク用 OS である MSX-DOS（いわゆる DOS1）と、その後継 MSX-DOS2 について、システムファイルの役割分担をまとめた資料である。対象は、DOS1 の MSXDOS.SYS と COMMAND.COM、DOS2 の MSXDOS2.SYS と COMMAND2.COM の計 4 ファイルである。「カーネルはどこにあるのか」「起動時に各ファイルがどの順で何をするのか」「ファイル操作やエラー処理は誰の担当なのか」といった、ファイル単位の役割を明らかにすることが目的である。

構成は、まず MSX-DOS 編（第 2〜4 章）で DOS1 の起動と 2 ファイルの役割を述べ、続く第 5 章で DOS1 から DOS2 へ何が変わったかを要約し、MSX-DOS2 編（第 6〜9 章）で DOS2 の構成と 2 ファイルの役割を述べる形とした。DOS2 編は、DOS1 編との対比で読むと変更点が分かりやすい。

記述は、実ファイルを計測・文字列抽出・部分的に逆アセンブルし、公開技術資料と照合した結果に基づく。根拠の種類は次の 3 区分に分け、混同しないようにする。

|区分|意味|
|-|-|
|実測|対象バイナリ（またはディスクイメージ）から直接確認したこと|
|資料|公式仕様書等の公開技術資料で確認したこと|
|未確認|今回の照合範囲では確定できなかったこと。推測で断定はしない|

対象ファイルの実測値（サイズ、ハッシュ、バージョン）は第 10 章にまとめた。未確認の事項も第 10 章に集約してある。

## 1.2 二つの DOS の位置づけ

- **MSX-DOS（DOS1）**は 1984 年に Microsoft が開発した、MSX 用のディスクオペレーティングシステムである。CP/M 互換の FCB（ファイルコントロールブロック）によるファイル操作を基本とし、メモリマッパーのない 64KB RAM の機械でも動作する。（資料）
- **MSX-DOS2** は 1988 年に ASCII が開発した後継で、サブディレクトリ、ファイルハンドル、環境アイテム、リダイレクト／パイプなどを備える。動作にはメモリマッパーが必須である。（資料）
- どちらのシステムも、ディスク上には 2 本のシステムファイルが置かれる。そして**カーネル（ファンクションコールの処理実体）は、DOS1・DOS2 ともディスク ROM の中にある**。システムファイル（MSXDOS.SYS／MSXDOS2.SYS）はどちらの世代でも RAM 側の構成要素であり、ファンクションコールの入口と DOS 環境の確立、シェルのロード、エラー／終了のデフォルト処理を担う。世代間の違いは、カーネルの規模と、その ROM の置かれ方にある。turboR では DOS1 カーネルと DOS2 カーネルが同一スロットに併存し、バンク切り替えで切り替わる。一方、MSX2+ 以前の機械のディスク ROM には DOS1 カーネルだけがあり、DOS2 を使う場合は別スロットに DOS2 カーネル ROM のカートリッジを装着する。（資料）
- 本書で対象としたファイルのバージョンは次の通りである（いずれも実測）。

|システム|ファイル|バージョン|
|-|-|-|
|MSX-DOS|MSXDOS.SYS|1.03（Copyright 1984 by Microsoft）|
|MSX-DOS|COMMAND.COM|1.11|
|MSX-DOS2|MSXDOS2.SYS|2.20（Copyright (1988) ASCII Corporation）|
|MSX-DOS2|COMMAND2.COM|2.20（Copyright (1988) ASCII Corporation）|

# 第2章 MSX-DOS の起動の流れ

DOS1 の起動は、ディスク ROM、ブートセクタ、MSXDOS.SYS、COMMAND.COM の 4 者が順にバトンを渡す流れである。DOS2 との大きな違いは、**ブートセクタのコードが実際にローダとして働く**ことにある。本章の記述は、対象ディスク（MSX_DOS_TOOLS.DSK）のブートセクタと MSXDOS.SYS の実測に基づく。

## 2.1 ブートセクタがローダを担う

- 電源投入後、ディスク ROM が初期化されてディスクシステムを統括する。ブート可能なディスクがある場合、ディスク ROM はブートセクタの先頭 100h バイトを C000h にコピーし、C01Eh をキャリークリアで呼ぶ。（資料）
- 対象ディスクのブートセクタは EB FE 90 で始まり、OEM 名「MSX_04」、BPB（512 バイト／セクタ、2 セクタ／クラスタ、FAT 2 本、ルートディレクトリ 112 エントリ）を持つ。（実測）
- C01Eh のコードは C030h へジャンプし、そこにローダ本体が置かれている。ローダは FCB を使って「MSXDOS  SYS」を開くプログラムである。（実測）
  - FCB は C0ABh に組み立てられる（ファイル名文字列「MSXDOS  SYS」はブートセクタ内オフセット 0ACh に実測）。
  - ファンクションコールは 0F37Dh 経由で呼ぶ。これは DOS 環境が確立する前に使える、ディスク ROM 側のファンクション入口である。
  - _FOPEN（0Fh）で開き、_SETDTA（1Ah）で転送先を 0100h に設定し、レコードサイズ 1 で _RDBLK（27h）により最大 3F00h バイトを読み、最後に JP 0100h で MSXDOS.SYS へ跳ぶ。一連の呼び出しを逆アセンブルで確認した。（実測）
  - ファイルが開けなかった場合は、文字列「Boot error / Press any key for retry」を表示して再試行する。（実測）
- DOS2 では、このブートセクタのコードはシステム起動には使われない（6.2 節）。同じ形式のブートセクタが、DOS1 では現役のローダ、DOS2 では名残、という対照になっている。

## 2.2 MSXDOS.SYS の初期化と再配置

- MSXDOS.SYS は 0100h で実行を開始する。ファイル先頭は JP 0200h で、0200h（ファイルオフセット 0100h）にはバナー文字列を飛び越える JR 命令があり、その先（ファイルオフセット 0138h）から初期化コードが始まる。（実測）
- バナー文字列「MSX-DOS version 1.03 / Copyright 1984 by Microsoft」はファイルオフセット 0102h から置かれている。（実測）
- 初期化コードはスタックを設定し、スロット関連の初期化を行った後、**リロケーションテーブルを走査してアドレスを修正するループ**を実行する。テーブルはファイル先頭の JP 命令の直後（アドレス 0103h）から始まり、0000h を終端として、各エントリが指すバイトに再配置ベースの上位バイトを加算する処理を逆アセンブルで確認した。（実測）
- この再配置により、MSXDOS.SYS はメモリ上部のシステム領域へ置かれて常駐する。あわせて 0005h にファンクションコール入口が設定され、アプリケーションプログラムはこの入口を通じてディスク ROM 内のカーネルを呼べるようになる。（資料）
- 再配置先アドレスの正確な決定方法は、初期化コードの全逆アセンブルをしていないため未確認である（10.4 節）。

## 2.3 COMMAND.COM の起動と AUTOEXEC.BAT

- DOS 環境の準備ができると、MSXDOS.SYS が COMMAND.COM をロードして起動する。（資料）
- COMMAND.COM は、ルートディレクトリに AUTOEXEC.BAT があればそれを実行する。COMMAND.COM 内に「AUTOEXECBAT」のファイル名文字列がある。（資料／実測）
- AUTOEXEC.BAT が無い場合は、起動時に日付と時刻の入力を求める。COMMAND.COM 内に「Current date is」「Enter new date:」「Current time is」「Enter new time:」の文字列がある（DATE／TIME コマンドと共用の表示部品でもある）。（実測）
- 対象ディスクに実際に置かれていた AUTOEXEC.BAT は次の通りである。（実測）

```bat
mode 29
type welcome.doc
pause （日本語の案内文）
mode 40
mode 80
cls
```

- MODE は内部コマンドだが、最後の `cls` は内部コマンドではない。そのため、このディスクには CLS.COM が外部コマンドとして別途置かれている（ディレクトリ一覧で実測）。DOS1 のシェルの機能範囲がうかがえる実例である。

# 第3章 MSXDOS.SYS の役割

MSXDOS.SYS は、ファンクションコールの処理実体ではない。DOS1 のカーネルも DOS2 と同様にディスク ROM の中にあり、MSXDOS.SYS は RAM 側のシステム構成要素である。ブートセクタのローダで 0100h へ読み込まれ、メモリ上部のシステム領域へリロケートして、ファンクションコールの入口と DOS 環境を整え、COMMAND.COM を起動する。本章では、RAM 常駐部としての役割、ファンクションの一覧、ディスクエラーと終了のデフォルト処理、COMMAND.COM のロード／再ロード、内部構造の観察の順に述べる。

## 3.1 RAM 側のシステム構成要素としての MSXDOS.SYS

- アプリケーションプログラムが使うファンクションコール（C レジスタに機能番号を入れて 0005h を CALL）の処理実体は、ディスク ROM 内のカーネルにある。MSXDOS.SYS はその入口（0005h）と呼び出し環境を担い、起動時にメモリ上部のシステム領域へ再配置されて常駐する（2.2 節）。（資料／実測）
- ファイルサイズは 2,432 バイトと小さい。この中には、ファンクションコールの入口まわり、DOS 環境の確立、COMMAND.COM のロード／再ロード、ディスクエラーのメッセージなどが収められている（文字列の実測は 3.3 節）。ファンクションコールの処理実体と FAT ファイルシステム、低レベルのディスク読み書きは、ディスク ROM 側（カーネルとドライバ）が担う分担である。（実測／資料）
- ファイル操作の API は FCB のみである。ファイルハンドル（DOS2 の 43h _OPEN など）は存在しない。（資料）
- サブディレクトリは扱わない。ディレクトリはルートのみのフラットな構造で、パス文字列を解釈する仕組みも無い。（資料）
- 環境変数（DOS2 の環境アイテム）に相当する仕組みも無い。（資料）

## 3.2 ファンクションコール（00h〜30h）

DOS1 のファンクションは 00h〜30h の範囲で、すべて CP/M 互換の系譜にある。一覧は、MSX-DOS2 Function Specification の一覧で「MSX1」互換と表示される範囲に基づく（資料）。なお 31h _DPARM は同資料で DOS2 の新設と明記されており、DOS1 には無い。

|番号|名前|機能|
|-|-|-|
|00h|_TERM0|プログラム終了|
|01h|_CONIN|コンソール入力（エコー付き）|
|02h|_CONOUT|コンソール出力|
|03h/04h|_AUXIN/_AUXOUT|補助入出力|
|05h|_LSTOUT|プリンタ出力|
|06h|_DIRIO|ダイレクトコンソール I/O|
|07h/08h|_DIRIN/_INNOE|コンソール入力（エコーなし）|
|09h|_STROUT|文字列出力（$ 終端）|
|0Ah|_BUFIN|バッファ付き行入力|
|0Bh|_CONST|コンソールステータス|
|0Ch|_CPMVER|バージョン番号取得|
|0Dh|_DSKRST|ディスクリセット|
|0Eh|_SELDSK|ドライブ選択|
|0Fh〜17h|_FOPEN/_FCLOSE/_SFIRST/_SNEXT/_FDEL/_RDSEQ/_WRSEQ/_FMAKE/_FREN|FCB によるファイル操作|
|18h|_LOGIN|ログインベクタ取得|
|19h|_CURDRV|カレントドライブ取得|
|1Ah|_SETDTA|転送アドレス設定|
|1Bh|_ALLOC|アロケーション情報取得|
|21h〜24h|_RDRND/_WRRND/_FSIZE/_SETRND|FCB ランダム入出力|
|26h/27h|_WRBLK/_RDBLK|FCB ブロック書き込み／読み出し|
|28h|_WRZER|ゼロ埋めランダム書き込み|
|2Ah〜2Dh|_GDATE/_SDATE/_GTIME/_STIME|日付・時刻の取得／設定|
|2Eh|_VFY|ベリファイフラグ設定|
|2Fh/30h|_RDABS/_WRABS|絶対セクタ読み書き|

- 実装されているのは 42 機能である（1Ch〜20h、25h、29h は DOS1／DOS2 とも未使用）。
- DOS2 の互換系一覧（7.5 節）と見比べると、DOS2 側では 31h _DPARM が追加されているほかは同等であり、DOS1 のプログラムは原則として DOS2 でも動作する互換性が保たれている。

## 3.3 ディスクエラーとプログラム終了のデフォルト処理

ディスクエラーが発生したときのユーザーへの問い合わせや、プログラム終了の受け口は、MSXDOS.SYS の常駐部が受け持つ。DOS1 ではエラー説明をコードから生成する仕組み（DOS2 の _EXPLAIN）はなく、メッセージは固定文字列である。MSXDOS.SYS 内に次の文字列を確認した。（実測）

|文字列|用途|
|-|-|
|Bad FAT, drive A|FAT 破損の通知（ドライブ文字は実行時に変わる）|
|Write protect / Not ready / Unsupported media type|エラーの種別|
|Disk error reading drive A（部品文字列 reading / writing / drive）|エラー発生箇所の表示|
|Abort, Retry, Ignore? |応答プロンプト|
|Terminate batch file (Y/N)? |バッチ実行中のアボート時の問い合わせ|
|Insert DOS disk in default drive / and strike any key when ready|COMMAND.COM の再ロードに失敗したときの入れ替え要求|
|COMMAND COM|再ロード対象のファイル名|

注目すべきは「Terminate batch file (Y/N)?」の所在である。DOS2 ではこの問い合わせは COMMAND2.COM の担当だった（8.3 節）が、DOS1 では MSXDOS.SYS 側にある。バッチ実行の状態を常駐側が把握し、アボート処理と一体で問い合わせる作りと見られる。

## 3.4 COMMAND.COM のロードと再ロード

- 起動時、MSXDOS.SYS が COMMAND.COM をロードして実行する。（資料）
- トランジェントプログラムの実行中、COMMAND.COM のトランジェント部は上書きされうる。プログラム終了後に再ロードが必要な場合、その面倒は MSXDOS.SYS 側が見る作りで、ファイル名「COMMAND COM」と、ディスク入れ替えを促す文字列が MSXDOS.SYS 内にある。（実測）
- DOS2 では再ロード先を環境アイテム SHELL で切り替える運用が可能だったが、DOS1 にはその仕組みはなく、デフォルトドライブのルートから読み直す固定の動作である。（資料）

## 3.5 内部構造についての観察（参考）

本節は実測で得た観察であり、確定に至っていない点は 10.4 節に挙げた。

- ファイル先頭 3 バイトは JP 0200h で、その直後に**単調増加する 16 ビットオフセットの表（70 エントリ、0000h 終端）**が置かれ、0100h まで埋め草が続く。（実測）
- この表がリロケーションテーブルであり、初期化コードが走査してアドレス修正に使うことは 2.2 節の通りである。（実測）
- バージョンバナーはファイルオフセット 0102h から（CRLF、「MSX-DOS version 1.03 / Copyright 1984 by Microsoft」、「$」）置かれている。（実測）

# 第4章 COMMAND.COM の役割

COMMAND.COM は**コマンドインタプリタ（シェル）**である。MSXDOS.SYS から起動され、ユーザーとの対話、コマンドの解釈と実行を担う。機能範囲は DOS2 の COMMAND2.COM より明確に狭く、内部コマンドは 14 種、リダイレクトや環境変数の仕組みは持たない。

## 4.1 プロンプトとコマンド行入力

- カレントドライブを示すプロンプト（「A>」形式）を表示し、コマンド行を読む。サブディレクトリが無いため、プロンプトにディレクトリを含める概念はない。（資料）
- 行入力はカーネルのバッファ付き行入力（0Ah _BUFIN）を使う。DOS2 世代のような履歴呼び出し等の編集機能が DOS1 の _BUFIN にどこまであったかは未確認である（10.4 節）。
- 起動時の日付・時刻の問い合わせについては 2.3 節を参照。

## 4.2 内部コマンド

内部コマンドは、COMMAND.COM 内のコマンドディスパッチテーブルをバイナリから直接パースして確定した。テーブルはファイルオフセット 1398h にあり、8 バイトの空白詰めコマンド名＋2 バイトのハンドラ値の組が並ぶ。（実測）

|コマンド|ハンドラ値|役割|備考|
|-|-|-|-|
|DIR|0992h|ファイル名一覧||
|COPY|0BF0h|ファイルコピー||
|TYPE|0B25h|ファイル内容の表示||
|REN|0B77h|名前変更|RENAME と同一ハンドラ（短縮形）|
|DEL|0B8Ah|ファイル削除|ERASE と同一ハンドラ|
|DATE|0F96h|日付の表示／設定||
|TIME|1085h|時刻の表示／設定||
|RENAME|0B77h|名前変更|REN と同一ハンドラ|
|ERASE|0B8Ah|ファイル削除|DEL と同一ハンドラ|
|PAUSE|0B71h|キー入力待ち||
|REM|0801h|コメント||
|VERIFY|0BC5h|ベリファイ状態の表示／設定|カーネル 2Eh _VFY のフロントエンド|
|MODE|1108h|画面モード変更||
|BASIC|1150h|disk BASIC へ移行||
|FORMAT|1156h|ディスクのフォーマット||

- テーブルは全 15 エントリ。REN は RENAME の短縮形、ERASE は DEL の別名で、それぞれ同一ハンドラを指す。実質のコマンドは **14 種**、ハンドラを共有する別名を除いた処理の実体は 13 種である。14 種という数え方は MSX Wiki の DOS1 内部コマンド一覧とも一致する。（実測／資料）
- BASIC と FORMAT のハンドラは隣接した小さな入口であり、どちらも ROM 側の機能（disk BASIC、ディスク ROM のフォーマットルーチン）への橋渡しと見られる。
- DOS2 の COMMAND2.COM（34 種、8.2 節）と比べると半分以下である。サブディレクトリ系（CD/MD/RD）、SET、PATH、ECHO、EXIT、HELP、VER、CLS、VOL などは無い。CLS が無いことは、対象ディスクの AUTOEXEC.BAT が外部の CLS.COM に頼っていることからも裏付けられる（2.3 節）。

## 4.3 外部プログラムの検索・ロード・実行

- 入力された名前が内部コマンドでない場合、拡張子 .COM、次に .BAT のファイルを探す。探す範囲は**カレントドライブのルートディレクトリのみ**で、PATH のような検索パスの仕組みは無い。（資料）
- .COM が見つかれば 0100h にロードして実行する。COMMAND.COM は常駐部を残して本体領域を実行中プログラムに明け渡し、プログラムが終了すると制御を取り戻す。再ロードが必要な場合の処理は MSXDOS.SYS 側と分担する（3.4 節）。（資料）
- エラーメッセージとして「Invalid drive specification」「Bad command or file name」「Program too big to fit in memory」を内蔵する。（実測）
- プログラムの終了コードを保持・参照する仕組み（DOS2 の _TERM や環境アイテム PROGRAM/PARAMETERS に相当するもの）は無い。（資料）

## 4.4 バッチファイル

- .BAT は 1 行ずつ読んで、キーボードから打ったのと同じに実行する。%0〜%9 のパラメータ置換（%0 はバッチ名自身）を行う。（資料）
- 行エコーの制御は無い。ECHO コマンド自体が内部コマンドに存在しない（4.2 節のテーブルに無いことを実測）。対象ディスクの AUTOEXEC.BAT もエコー制御なしで書かれている。
- 実行中のコマンドが中断されると「Terminate batch file (Y/N)?」と問い合わせるが、このプロンプトは MSXDOS.SYS（常駐部）の担当である（3.3 節）。（実測）
- バッチファイルのあるディスクが抜かれている場合は「Insert disk with batch file / and strike any key when ready」と促す。この文字列は COMMAND.COM 側にある。（実測）
- バッチから別のバッチを呼ぶとチェーンになり戻らない、という挙動は DOS2 と同様である。（資料）

## 4.5 DOS1 のシェルに無いもの

DOS2 のシェルとの対比で、DOS1 の COMMAND.COM に無いものを整理する。いずれも、ディスパッチテーブルと文字列の不在（実測）と公開資料（資料）の双方で確認した。

- リダイレクト（<、>、>>）とパイプ（|）の解釈
- 環境変数／環境アイテム（SET コマンド自体が無い）
- PATH によるコマンド検索
- サブディレクトリの操作（CD/MD/RD、カレントディレクトリの概念）
- EXIT コマンド（DOS を抜ける内部コマンドは BASIC のみ）

これらはすべて DOS2 で追加されたものである（第 5 章）。

## 4.6 内部構造についての観察（参考）

- ファイル先頭 3 バイトは JP 0500h で、その直後に MSXDOS.SYS と同じ形式の**リロケーションテーブル（473 エントリ、0000h 終端）**が置かれ、コードはファイルオフセット 0400h から始まる。（実測）
- バージョン文字列「COMMAND version 1.11」はファイルオフセット 0586h にある。（実測）
- 「AUTOEXECBAT」（8.3 形式のファイル名）や「$$DOS」の文字列も内蔵する。（実測）
- ファイル末尾付近（オフセット 1938h）に「MSX-DOS version 2.2 by Tim Paterson 03/06/84」という文字列が残存している。（実測）これは MSX-DOS の原典である MS-DOS 2.2 のクレジットで、実行時に表示されるものではない。MSX-DOS が MS-DOS のコード系統を受け継いでいる痕跡と見られる。
- リロケーションテーブルが MSXDOS.SYS の 70 エントリに対して 473 エントリと大きいことから、COMMAND.COM では再配置を要する部分の割合が大きいことがうかがえる。どの部分の再配置に使われるかの確定は未確認である（10.4 節）。

# 第5章 MSX-DOS2 で何が変わったか

MSX-DOS2 編（第 6〜9 章）に入る前に、DOS1（第 2〜4 章）から DOS2 へ何が変わったかを要約する。変更は「構成の変化」と「機能の追加」に大別できる。

## 5.1 変更点の要約

|項目|MSX-DOS（DOS1）|MSX-DOS2|
|-|-|-|
|カーネルの置き場所|ディスク ROM 内|ディスク ROM 32KB 内（マッパー RAM へコピーして実行）|
|カーネル ROM の置かれ方|ディスク ROM に DOS1 カーネルのみ（MSX2+ 以前）。turboR では DOS2 カーネルと同一スロットに併存|turboR では DOS1 カーネルと同一スロット（バンク切り替え）。MSX2+ 以前では別スロットにカートリッジで装着|
|システムファイルの役割|MSXDOS.SYS＝RAM 側の構成要素（入口と環境の確立、COMMAND.COM のロード、エラー／終了のデフォルト処理。2,432 バイト）|MSXDOS2.SYS＝入口と環境の確立のみ（4,480 バイト）|
|ブートセクタの役割|ローダ本体（FCB で MSXDOS.SYS を読む）|システム起動には使われない|
|ファイル API|FCB のみ（00h〜30h、42 機能）|FCB 互換＋ハンドル系を新設（40h〜70h、31h _DPARM も追加）|
|サブディレクトリ|無し（ルートのみ）|対応（CD/MD/RD。パスの解釈はカーネル）|
|環境変数|無し|環境アイテム（保持はカーネル、SET が窓口）|
|リダイレクト／パイプ|無し|COMMAND2 が解釈（パイプは一時ファイル経由）|
|コマンド検索|カレントドライブのルートのみ|PATH 環境アイテムによる検索|
|内部コマンド|14 種（テーブル 15 エントリ）|34 種＋別名|
|バッチ|%置換あり。終了問い合わせは MSXDOS.SYS 側|%置換＋ECHO 制御。終了問い合わせは COMMAND2 側|
|起動時の日付・時刻|AUTOEXEC.BAT が無ければ問い合わせる|2.20 での切り分けは未確認（10.4 節）|
|メモリ要件|64KB RAM で動作（マッパー不要）|メモリマッパー必須（カーネルセグメントを確保）|
|エラーメッセージ|固定文字列（MSXDOS.SYS 内）|_EXPLAIN でコードから生成（日英の文字列を内蔵）|
|開発元・年|Microsoft、1984（MSXDOS.SYS 1.03）|ASCII、1988（2.20）|

## 5.2 構成の変化：カーネルの置かれ方と大規模化

カーネルがディスク ROM の中にある点は DOS1・DOS2 で共通している。構成面で変わったのは、カーネルの規模と、その ROM の置かれ方である。

- **カーネルの大規模化**：DOS2 のカーネルは、ファイルハンドル、サブディレクトリ、パスの解析、環境アイテム、文字デバイス、RAM ディスク管理などを抱えて DOS1 のカーネルよりはるかに大きく、ROM のページ 2 に 16KB が割かれている。（資料）
- DOS2 では、このカーネルが初期化時にマッパー RAM セグメントへコピーされ、ページ 0 にページインして実行される（6.1 節）。ROM から直接実行せず RAM へ展開することで、大きなカーネルを持ちながらトランジェントプログラム用の領域（TPA）を圧迫しない構成になっている。
- その代わり、DOS2 の動作にはメモリマッパーが必須になった。DOS1 が 64KB RAM で動作したのとは対照的である。
- **カーネル ROM の置かれ方**：turboR では、DOS1 カーネルと DOS2 カーネルが同一スロットに存在し、バンク切り替えで切り替わる仕組みになっている。MSX2+ 以前の機械では、ディスク ROM に DOS1 カーネルだけが存在し、DOS2 を使う場合は別スロットにカートリッジで DOS2 カーネル ROM を装着する形で動作する。（資料）
- システムファイル同士を比べると、MSXDOS2.SYS（4,480 バイト）は DOS1 の MSXDOS.SYS（2,432 バイト）より大きい。どちらもカーネル本体ではなく RAM 側の構成要素だが、DOS2 側はファンクションコールの入口コード（ページングとパラメータコピーを伴う）、COMMAND2.COM のロード、ディスクエラー／終了のデフォルト処理、日英両言語のエラーメッセージなどを担うためである（第 7 章）。
- 起動手順も変わった。DOS1 ではブートセクタ内のローダが MSXDOS.SYS を読んだが、DOS2 ではブートセクタのコードはシステム起動に使われず、ROM 側の仕組みが MSXDOS2.SYS を 0100h へ読み込む（6.2 節）。

## 5.3 機能の追加

シェルと API の両面で、DOS2 では次の機能が追加された。詳細は第 7・8 章で述べる。

- **ファイルハンドル API**：40h〜70h の新設ファンクション群。FCB の制約（ファイルごとに大きな作業領域が要る、ランダムアクセスが煩雑）を解消し、標準入出力やデバイス（CON、PRN 等）もハンドルで統一的に扱えるようになった。31h _DPARM も DOS2 の追加である。
- **サブディレクトリ**：階層ディレクトリとパス指定に対応。カーネルがパス文字列を解釈し、シェルには CD/MD/RD 系のコマンドが追加された。
- **環境アイテム**：名前付きの文字列をカーネルが保持する仕組み。SET が操作の窓口で、PATH、SHELL、TEMP、PROMPT などがシェルの動作を左右する。「保持＝カーネル、解釈＝各利用者」という分担が DOS2 の設計の特徴である（第 9 章）。
- **リダイレクトとパイプ**：コマンド行の <、>、>>、| を COMMAND2 が解釈する。パイプは一時ファイルを介して実現される。
- **PATH 検索**：外部プログラムをカレントディレクトリ以外の場所からも探せるようになった。
- **内部コマンドの増加**：14 種から 34 種＋別名へ。ディレクトリ系、SET、PATH、ECHO、EXIT、HELP、VER、VOL、CONCAT、MOVE 系などが加わった。
- **エラー処理の高度化**：エラー説明を _EXPLAIN（66h）でコードから生成するようになり、プログラム側が自前のディスクエラールーチン／アボートルーチンを定義する口（_DEFAB 63h、_DEFER 64h）も用意された。
- **バッチの強化**：行エコーの制御（ECHO）が加わった。なお「Terminate batch file (Y/N)?」の問い合わせは、DOS1 では MSXDOS.SYS 側だったものが DOS2 では COMMAND2 側の担当に移っている。
- **その他**：RAM ディスク（_RAMD 68h と RAMDISK コマンド）、ディスクバッファ数の設定（_BUFFER 69h と BUFFERS コマンド）、論理ドライブ割り当て（_ASSIGN 6Ah と ASSIGN コマンド）など、カーネル機能とそのフロントエンドの組が増えた。

一方で、DOS1 のファンクション（00h〜30h）と内部コマンドの顔ぶれは DOS2 でもほぼそのまま引き継がれており、DOS1 向けのプログラムと操作感の互換性は保たれている。

# 第6章 MSX-DOS2 の構成と起動の流れ

MSX-DOS2 の側の構成と起動を述べる。カーネルがディスク ROM の中にある点は DOS1 と共通だが、DOS2 ではカーネルが大規模化し、初期化時にマッパー RAM へコピーしてページ 0 で実行する方式になった。カーネル ROM の置かれ方も機種で異なり、turboR では DOS1／DOS2 両カーネルが同一スロットに併存してバンク切り替えで選ばれるのに対し、MSX2+ 以前の機械では DOS2 カーネルは別スロットのカートリッジで供給される。こうした構成が、起動の流れから 2 ファイルの役割まで、DOS2 の設計全体を決めている。

## 6.1 三層構造の全体像

まず押さえるべき点は、**MSX-DOS2 のカーネル本体は MSXDOS2.SYS ではなく、ディスク ROM（32KB）の中にある**ことである。

- システムは「32KB のディスク ROM」と「システムファイル MSXDOS2.SYS / COMMAND2.COM」から構成される。ROM にはマッパーサポート、DOS カーネル、disk BASIC、ディスクドライバが入る。（資料）
- DOS カーネルは ROM のページ 2（8000h〜BFFFh）に置かれるが、初期化時にマッパー RAM セグメントへコピーされ、ページ 0（0000h〜3FFFh）にページインして実行される。最上位 2 つのマッパーセグメントが「カーネルコードセグメント」と「カーネルデータセグメント」として恒常的に確保される。（資料）
- カーネル ROM の供給形態は機種によって異なる。turboR では DOS1 カーネルと DOS2 カーネルが同一スロットに収まり、バンク切り替えで切り替わる。MSX2+ 以前の機械のディスク ROM には DOS1 カーネルだけがあり、DOS2 は別スロットに装着した DOS2 カーネル ROM のカートリッジで動作する。（資料）
- ディスク側の 2 ファイルは、仕様書の言葉では「CP/M 互換のトランジェントプログラム環境（MSXDOS2.SYS）とコマンドインタプリタ（COMMAND2.COM）」を提供する。（資料）

つまり役割分担の大枠は次の通りである。

|層|実体|主な役割|
|-|-|-|
|ディスク ROM|カートリッジ／内蔵 ROM 32KB|DOS カーネル本体（ファンクションコール処理、FAT ファイルシステム）、disk BASIC、ディスクドライバ、マッパーサポート|
|MSXDOS2.SYS|ディスク上のファイル（RAM 常駐）|DOS 環境の確立、ファンクションコールの入口、COMMAND2.COM のロード、ディスクエラー／終了のデフォルト処理|
|COMMAND2.COM|ディスク上のファイル（トランジェント）|コマンド行インタプリタ（シェル）。内部コマンド、バッチ、リダイレクト／パイプ、プログラム実行|

## 6.2 起動の流れ

電源投入からコマンドプロンプトに至るまでの流れを、担当する層に注意しながら追う。

### 6.2.1 ディスク ROM の初期化

電源投入後、最初に初期化されたディスク ROM が「マスターディスク ROM」になり、ディスクシステムを統括する。カーネル（16KB）を ROM ページ 2 からカーネルコードセグメント（マッパー RAM）へコピーし、ページ 0 で実行してカーネルデータセグメント内のデータ構造を初期化する。これでファンクションコールが実行可能になる。（資料）

### 6.2.2 disk BASIC 環境のセットアップ

カーネルをページアウトし、ページ 3 にバッファを確保、ファンクションコール入口として 0F37Dh のスロット間ジャンプを設定する（BASIC 環境からはこの入口を使う）。ディスクエラー／終了処理用に DISKVECT / BREAKVECT の仕組みも用意される。（資料）

### 6.2.3 ブート第 1 段（ブートセクタ）

各ドライブからブートセクタを読み、先頭バイトが EBh または E9h なら先頭 100h バイトを C000h にコピーして C01Eh をキャリークリアで呼ぶ。これは専用アプリケーションに制御を渡すためのもので、通常はすぐ戻る。（資料）

- 対象ディスクのブートセクタは EB FE 90 で始まり、OEM 名「MSX_04」、文字列「Boot error / Press any key for retry」とファイル名「MSXDOS SYS」を含む。（実測）
- ただし MSX-DOS2 では**ブートセクタのコード自体はシステム起動には使われない**（MSX-DOS との相違点として仕様書が明記。DOS1 側のブートセクタの実測は 2.1 節）。ブートセクタ内に DOS1 式の名前が残っているのはその名残と見られる。（資料）

### 6.2.4 ブート第 2 段（MSXDOS2.SYS のロード）

ブートできたドライブをデフォルトドライブとし、ルートディレクトリから「MSXDOS2.SYS」を探す（無ければ各ドライブを探す）。見つかれば**ページ 0 の 0100h へ読み込んでジャンプ**する。0000h〜0100h にはスロット切替／割り込み用のジャンプと、0080h の空コマンドラインが既に用意されている。見つからなければ disk BASIC が起動する。（資料）

### 6.2.5 MSXDOS2.SYS の自己配置と DOS 環境の確立

MSXDOS2.SYS は自分をページ 3 の最上部へリロケートし、バッファ領域を確保する。0F37Dh の入口を自前の入口コードへ差し替え、0005h にもファンクションコール入口を設定する（両者は同一）。（資料）

### 6.2.6 COMMAND2.COM のロードと起動

MSXDOS2.SYS が COMMAND2.COM を読み込んで実行する。COMMAND2.COM は通常のトランジェントプログラムとして動作するが、0000h と 0005h のジャンプにフックし、小さな常駐部を残して他のプログラムを実行できる。（資料）

### 6.2.7 初期バッチの実行

- 電源投入時の自動起動では **AUTOEXEC.BAT** が実行される。パラメータ %1 には起動ドライブ（「A:」形式）が渡される。（資料）
- disk BASIC から `CALL SYSTEM` で入った場合は、渡されたコマンドが実行され、コマンドが無ければ **REBOOT.BAT** が実行される。（資料）
- MSXDOS2.SYS の内部には「A:\AUTOEXEC.BAT」「A:\REBOOT.BAT」「A:\COMMAND2.COM」のパス文字列が埋め込まれており（ドライブ文字は実行時に決まる）、起動時に実行すべき対象を COMMAND2 側へ渡す作りであることがうかがえる。（実測）

## 6.3 起動バッチの実例

対象ディスクに実際に置かれていたバッチファイルが、この流れの実例になっている。（実測）

```bat
rem AUTOEXEC.BAT（このディスクのもの）
ramdisk 4064/d
copy %1command2.com h:\
reboot.bat %1

rem REBOOT.BAT（このディスクのもの）
set temp=h:\
set shell=h:\command2.com
path %1\utils
```

最大サイズの RAM ディスク（H:）を作り、COMMAND2.COM をそこへコピーし、SHELL 環境アイテムを RAM ディスク側へ向け直すことで、シェルの再ロードを高速化する典型的な運用である。

# 第7章 MSXDOS2.SYS の役割

MSXDOS2.SYS は「カーネル本体」ではなく、**DOS 環境を成立させ、維持するための RAM 常駐コード**である。本章では、その役割を、起動時の初期化、COMMAND2.COM のロード、ディスクエラーと終了のデフォルト処理、ファンクションコールの入口の順に述べる。

## 7.1 DOS 環境の確立（起動時の初期化）

- 自身をページ 3 最上部へリロケートし、パラメータコピー用バッファ等を確保する。（資料）
- ファンクションコール入口を整備する。0F37Dh（disk BASIC 環境用だった入口）を自前の入口コードへ差し替え、0005h（トランジェントプログラム用入口）を設定する。入口コードは必要に応じてカーネルコード／データセグメントをページインし、パラメータをコピーしてカーネルのディスパッチャを呼ぶ。（資料）
- バージョン不一致やメモリ不足を検出すると、その場でシステムを止める。文字列「Wrong version of MSX-DOS, system halted」「Not enough memory, system halted」を内蔵する。（実測）

## 7.2 COMMAND2.COM のロードと再ロードの面倒

- 起動時に COMMAND2.COM をロードして実行する。（資料）
- COMMAND2.COM が見つからない／読み込めない場合は、ディスクの入れ替えを促す。文字列「Insert COMMAND2.COM disk in drive ○:」「Press any key to continue...」を内蔵する。（実測）
- 同じプロンプト文字列は COMMAND2.COM 側にもあり、そちらはシェル自身の再ロード時（8.3 節）に使われる。起動段の失敗は MSXDOS2.SYS 側、運用中の再ロードは COMMAND2.COM 側、という分担と見られる。

## 7.3 ディスクエラーとプログラム終了のデフォルト処理（常駐部）

MSX-DOS 環境では、ディスクエラーとプログラム終了は MSXDOS2.SYS の常駐コードが受け持つ（カーネル内の KDSK_VECT / KAB_VECT 経由）。（資料）

- ディスクエラーのデフォルト動作は、ユーザーへの問い合わせである。バイナリ末尾に、メッセージ部品「reading」「writing」「drive 」と応答プロンプト「Abort or Retry (A/R)?」「Abort, Retry or Ignore (A/R/I)?」を内蔵する。（実測）
- 表示形式は仕様書の例では「Not ready reading drive A: / Abort, Retry or Ignore (A/R/I)?」。エラーの説明文はエラーコードをファンクション 66h（_EXPLAIN）で文字列化して得る作りで、MSXDOS2.SYS 内のコードに `LD C,66h`（_EXPLAIN 呼び出し）のパターンを確認した。（資料／実測）
- メッセージは英語と日本語（Shift-JIS）の両方が末尾領域に収められている。（実測）
- Abort が選ばれた場合のデフォルト動作は、COMMAND2.COM へ戻ることである。（資料）
- トランジェントプログラムは、ファンクションコールで自前のディスクエラールーチン／アボートルーチンを定義して、このデフォルト処理に割り込むこともできる（63h _DEFAB、64h _DEFER）。（資料）

## 7.4 ファンクションコールの入口

アプリケーションプログラムが使うファンクションコール（C レジスタに機能番号を入れて 0005h を CALL）は、**処理実体がディスク ROM 内のカーネル**であり、MSXDOS2.SYS はその入口と呼び出し環境（ページング、パラメータコピー、スタック切替）を担う。disk BASIC 環境では入口が 0F37Dh になる。（資料）

機能は大きく、CP/M・MSX-DOS1 互換系（FCB 中心、00h〜）と、MSX-DOS2 で新設された系（ファイルハンドル中心、40h〜70h）に分かれる。次節以降の一覧は Function Specification の記載どおりである。（資料）

# 第8章 COMMAND2.COM の役割

COMMAND2.COM は**コマンドインタプリタ（シェル）**である。トランジェントプログラムの一種として MSXDOS2.SYS から起動され、ユーザーとの対話、コマンドの解釈と実行を担う。

## 8.1 プロンプトとコマンド行入力

- カレントドライブ（PROMPT 環境アイテムが ON のときはカレントディレクトリも）を含むプロンプトを表示し、コマンド行を読む。（資料）
- コマンド行には編集機能（カーソル移動、挿入／削除、過去のコマンドの履歴呼び出し＝最大 256 文字分）がある。（資料）
- なお、この行編集は COMMAND2 専用ではなく、カーネルのバッファ付き行入力（0Ah _BUFIN）を使うプログラム一般で利用できる。COMMAND2 もその利用者の一つ、という位置づけである。（資料）

## 8.2 内部コマンド

内部コマンドは、COMMAND2.COM 内のコマンドディスパッチテーブル（名前＋ハンドラアドレスの表）をバイナリから直接パースして確定した。（実測）

|コマンド|役割|備考|

|ATDIR|ディレクトリの属性変更||
|ATTRIB|ファイルの属性変更|カーネル 50h 系|
|BASIC|disk BASIC へ移行||

- 内部コマンドの多くは、カーネルファンクションを呼び出す「薄いフロントエンド」である（ASSIGN、BUFFERS、FORMAT、RAMDISK、SET など）。実際の処理はカーネル側にある。
- COMMAND2.COM には HELP 用の「標準コマンド一覧」テキストが全文埋め込まれており、そこには CHKDSK、DISKCOPY、FIXDISK、KMODE、UNDEL、XCOPY、XDIR も載っている。しかし**これらはディスパッチテーブルに存在しない**ため、内部コマンドではなく別ファイルの外部ユーティリティである。HELP の一覧は内部／外部を区別せず「標準コマンド」として列挙している点に注意。（実測）

## 8.3 外部プログラムの検索・ロード・実行

- 入力された名前が内部コマンドでない場合、カレントディレクトリ、次に PATH 環境アイテムの検索パスの順に、拡張子 .COM、.BAT のファイルを探す。（資料）
- .COM が見つかれば TPA の 0100h にロードして実行する。実行に際して COMMAND2 は環境アイテム PROGRAM（プログラム名）と PARAMETERS（パラメータ）を設定し、終了時に取り除く。（資料）
- COMMAND2 自身は 0000h／0005h のジャンプにフックした小常駐部だけを残し、本体の領域は実行中プログラムに明け渡される。プログラムが終了すると常駐部が制御を取り戻す。（資料）
- 終了したプログラムがエラーコードを持っていた場合のメッセージ表示（「*** 」で始まる形式の文字列を内蔵）や、バッチ実行中の異常終了時の「Terminate batch file (Y/N)?」の問い合わせは COMMAND2 の担当である。（実測／資料）
- 終了後は必要に応じて自分自身をディスクから再ロードする。再ロード先は環境アイテム SHELL が指すファイルで、失敗したら元のロード元ドライブのルートから試す。ディスクが入っていない場合は「Insert COMMAND2.COM disk in drive ○:」と促す（この文字列も内蔵）。（資料／実測）
- 対象ディスクの AUTOEXEC/REBOOT が SHELL を RAM ディスクへ向け直しているのは、この再ロードを高速化するためである。（実測）

## 8.4 バッチファイル

- .BAT は 1 行ずつ読んで、キーボードから打ったのと同じに実行する。%0〜%9 のパラメータ置換（%0 はバッチ名自身、%% は % そのもの）を行う。（資料）
- 行のエコーは環境アイテム ECHO（ON/OFF）で制御する。（資料）
- バッチから別のバッチを呼ぶと**チェーン**になり、呼び出し元へは戻らない。ネストしたい場合は COMMAND2 コマンド（＝COMMAND2.COM の再帰実行）を使う。（資料）
- 実行中のコマンドが Ctrl-C 等で中断されると「Terminate batch file (Y/N)?」と問い合わせる。バッチファイルのあるディスクが抜かれている場合は「Insert batch file disk in drive ○:」と促す。どちらの文字列もバイナリ内に確認した。（資料／実測）

## 8.5 リダイレクトとパイプ

- コマンド行の `<`（入力）、`>` / `>>`（出力／追加）、`|`（パイプ）の解釈は COMMAND2 が行う。（資料）
- 実体となる標準ハンドルの付け替えはカーネル側の仕組み（70h _REDIR で状態を取得／設定できる）を使う。（資料）
- パイプは一時ファイルを介して実現される。COMMAND2.COM 内に、一時ファイル名のテンプレート「%PIPE00.$$$」と、環境アイテム TEMP の名前が確認できる。（実測）
- TEMP がパイプ用一時ファイルの置き場所を指す、というのが 2.20 世代の一般的な理解だが、今回照合した v2.00 の Command Specification には TEMP / UPPER / REDIR の環境アイテムとしての説明が無く、この点は未確認とする（10.4 節）。

## 8.6 環境アイテムの操作窓口

- 環境アイテムの**保持と読み書きの機構はカーネル**にある（6Bh _GENV / 6Ch _SENV / 6Dh _FENV）。値はカーネルデータ領域側に保持され、プログラムが終了しても残る。（資料）
- COMMAND2 はその操作窓口である。SET コマンドによる表示／設定／削除、PATH コマンド（実体は環境アイテム PATH の操作）、PROMPT の解釈（プロンプト表示の切り替え）などを担う。（資料）
- COMMAND2.COM 内には、環境アイテム名のテーブル（DATE、TIME、ECHO、HELP、PATH、PROMPT、PARAMETERS、PROGRAM、TEMP、UPPER、REDIR）と、デフォルト値のテーブル（SHELL = A:\COMMAND2.COM、HELP = A:\HELP など、ドライブ文字は起動時に調整される）を確認した。（実測）
- 仕様書で意味が確認できた主な環境アイテムは次の通りである。（資料）

|環境アイテム|意味|
|-|-|
|ECHO|バッチ行のエコー ON/OFF|
|PROMPT|ON でプロンプトにカレントディレクトリを含める|
|PATH|コマンド検索パス（PATH コマンドが操作する実体）|
|SHELL|COMMAND2.COM の在りか（自己再ロード用）|
|TIME / DATE|時刻・日付の表示形式|
|HELP|HELP コマンドが詳細テキストを読むディレクトリ（デフォルトは起動ドライブの \HELP）|
|APPEND|CP/M プログラムのファイル検索を助ける代替ディレクトリ。**これはカーネルが FCB オープン時に解釈する**もので、シェル側の解釈ではない（境界の好例）|
|PROGRAM / PARAMETERS|COMMAND2 がプログラム実行時に設定する|

## 8.7 HELP

- 引数なしの HELP は、COMMAND2.COM に埋め込まれた標準コマンド一覧テキストを表示する（全文をバイナリ内に確認した）。（実測）
- コマンド名を指定した HELP は、環境アイテム HELP のディレクトリにあるファイルから詳細を読む（対象ディスクにも HELP ディレクトリが存在する）。（資料／実測）

# 第9章 MSX-DOS2 における両者の境界

## 9.1 対比表

## 9.2 要点

要点は 3 つある。

1. **カーネル（ROM）と MSXDOS2.SYS は別物**。MSXDOS2.SYS はカーネルの「入口と番人」であり、ファイルシステムそのものは ROM 側にある。
2. **環境アイテムは「保持＝カーネル、解釈＝各利用者」**。SET は窓口にすぎず、APPEND のようにカーネル自身が解釈するもの、SHELL のように COMMAND2 自身が解釈するものがある。
3. **エラー処理は二層**。ディスクエラーの A/R/I 問い合わせは MSXDOS2.SYS 常駐部、コマンドやプログラムのエラーメッセージ表示は COMMAND2、という分担になっている。

## 10.2 実測で分かったこと

**MSX-DOS（DOS1）について**

- 対象ディスクのブートセクタに、FCB を使って MSXDOS.SYS を 0100h へ読み JP 0100h で跳ぶローダが置かれていること。呼び出しは 0F37Dh 経由で、_FOPEN（0Fh）、_SETDTA（1Ah）、_RDBLK（27h）の順であること。開けない場合は「Boot error / Press any key for retry」を表示すること。
- MSXDOS.SYS の初期化コードに、リロケーションテーブル（70 エントリ、0000h 終端、アドレス 0103h から）を走査してアドレスバイトを修正するループがあること。
- MSXDOS.SYS 内のエラーメッセージ群（Bad FAT、Write protect、Not ready、Unsupported media type、Abort, Retry, Ignore?、Terminate batch file (Y/N)?、Insert DOS disk in default drive）と、再ロード対象のファイル名「COMMAND COM」の所在。
- COMMAND.COM の内部コマンドのディスパッチテーブル（ファイルオフセット 1398h、15 エントリ）。REN＝RENAME、DEL＝ERASE が同一ハンドラであること。
- COMMAND.COM のリロケーションテーブルが 473 エントリあること。バージョン文字列の位置（0586h）。末尾付近（1938h）に「MSX-DOS version 2.2 by Tim Paterson 03/06/84」の文字列が残存していること。
- 対象ディスクの AUTOEXEC.BAT の内容と、CLS が外部コマンド（CLS.COM）として置かれていること。

**MSX-DOS2 について**

- 両ファイルのサイズ、ハッシュ、バージョン（2.20、Copyright (1988) ASCII Corporation）。DSK イメージ内の正本と一致。
- MSXDOS2.SYS 内のパス文字列（AUTOEXEC.BAT / REBOOT.BAT / COMMAND2.COM）、エラープロンプトの部品文字列、英語／日本語メッセージ、致命的エラーの文字列。
- MSXDOS2.SYS 内に _EXPLAIN（66h）を呼ぶコードパターンがあること。類似コードが複数ベースアドレス向けに収められていること。先頭付近に 17 エントリのジャンプテーブルがあること。
- COMMAND2.COM の内部コマンド一覧（ディスパッチテーブルをパースして確定。別名含む）。HELP の一覧に載るがテーブルに無い 7 コマンド（CHKDSK、DISKCOPY、FIXDISK、KMODE、UNDEL、XCOPY、XDIR）が外部ユーティリティであること。
- COMMAND2.COM 内の環境アイテム名テーブル、デフォルト値テーブル（SHELL、HELP）、パイプ一時ファイルのテンプレート「%PIPE00.$$$」。
- 対象ディスクの AUTOEXEC.BAT / REBOOT.BAT の内容（RAM ディスク＋SHELL 向け直しの実例）。

## 10.3 公開資料で分かったこと

**MSX-DOS（DOS1）について**

- DOS1 のファンクションが 00h〜30h の 42 機能であり、31h _DPARM は DOS2 の新設であること（MSX-DOS2 Function Specification の「MSX1」互換表示と NEW 表示）。
- DOS1 の内部コマンドが 14 種という数え方（MSX Wiki）。
- DOS1 にはサブディレクトリ、ファイルハンドル、環境変数、リダイレクト／パイプ、PATH 検索の仕組みが無いこと。

**MSX-DOS2 について**

- システム構成（ROM 32KB の内訳、カーネルのコピーと実行方式、カーネルコード／データセグメント）。
- 起動手順の全体（ROM 初期化 → ブートセクタ第 1 段 → MSXDOS2.SYS ロード（0100h）→ リロケート → COMMAND2 起動 → AUTOEXEC/REBOOT）。
- ファンクションコールの一覧（番号・名前・機能）と、DOS2 新設系が 40h〜70h であること。
- 環境アイテムのうち ECHO、PROMPT、PATH、SHELL、TIME、DATE、HELP、APPEND、PROGRAM、PARAMETERS の意味。
- バッチの仕様（%置換、チェーンとネストの違い、ECHO 制御、%1 = 起動ドライブ）。
- ディスクエラー処理の流れ（KDSK_VECT → デフォルトは MSXDOS2.SYS 常駐部がプロンプト、Abort で COMMAND2 へ）。

## 10.4 未確認点

次の事項は、今回の照合範囲では確定できなかった。推測で断定はしない。

**MSX-DOS（DOS1）について**

- MSXDOS.SYS のリロケーション先アドレスの正確な決定方法（空きメモリの測り方）。初期化コードの全逆アセンブルはしていない。
- COMMAND.COM のリロケーションテーブル（473 エントリ）が、どの部分（常駐部か全体か）の再配置に使われるか。
- COMMAND.COM のディスパッチテーブルのハンドラ値（0992h 等）が、ロードアドレス 0100h 基準か再配置後の基準か。本書ではテーブルの生値をそのまま記録した。
- DOS1 の _BUFIN（0Ah）での行編集の範囲（カーソル編集や履歴の有無）。
- DOS1 の起動時に COMMAND.COM が日付・時刻を尋ねる条件の正確な切り分け（AUTOEXEC.BAT の有無との関係は、文字列の実測と資料上の一般論に拠った）。

**MSX-DOS2 について**

- MSXDOS2.SYS の複数ベースアドレス向けコードの正確な使い分け（リロケーション先の決定方法）。確定には逆アセンブルが必要。
- MSXDOS2.SYS 先頭付近の 17 エントリ・ジャンプテーブルの用途。
- 環境アイテム TEMP、UPPER、REDIR の正確な意味づけ。バイナリ内の名前テーブルには存在するが、照合した v2.00 Command Specification には説明がない（2.20 で追加・変更された可能性があり、2.20 世代のユーザーズマニュアル等での確認が必要）。
- AUTOEXEC.BAT が無い場合に COMMAND2 が起動時に日付・時刻を尋ねる、という一般に知られた挙動。COMMAND2.COM 内に「Current date is」「Enter new date」等の文字列はあるが、これが起動時問い合わせ用か DATE コマンド用かの切り分けは今回できていない。DOS1 側では同じ文字列が COMMAND.COM にあり DOS1 では起動時問い合わせが知られているが、DOS2 2.20 での扱いは別途確認が必要である。
- 終了コードをバッチファイルから条件分岐に使う手段（MS-DOS の ERRORLEVEL 相当）が 2.20 の COMMAND2 にあるかどうか。今回は確認できていない。

## 10.5 資料の版についての注意

- DOS2 側のバイナリは 2.20（1988）だが、照合に使った System / Command Specification は 2.00（1986-11-26 / 1986-12-8）の文書である。基本構造は 2.20 でも踏襲されているが、細部（環境アイテムの追加など）には差異がありうる。Function Specification は 2.20 対応の写しを参照した。
- DOS1 側のファンクション一覧は、DOS2 の Function Specification に付された「MSX1」互換表示に拠った。DOS1 自体の公式仕様書との直接照合はしていない。
