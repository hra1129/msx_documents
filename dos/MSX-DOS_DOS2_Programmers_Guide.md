# 第1章 ファンクションコールの基礎

## 1.1 本書の目的と記号

本書は、MSX-DOS および MSX-DOS2 の上で動作するアプリケーション（主に .COM 形式の機械語プログラム）を書くための、ファンクションコールの実践的な解説書である。呼び出し方、FCB（ファイルコントロールブロック）とファイルハンドルの扱い、全ファンクションのリファレンスを、実際に動作するサンプルプログラムとともに示す。

MSX-DOS（以下 DOS1）と MSX-DOS2（以下 DOS2）は、ファンクションコールの体系を共有しながら、DOS2 で大幅な拡張が行われている。本書では各項目・各ファンクションに次の記号を付け、どちらの環境の話であるかを一目で分かるようにした。

| 記号 | 意味 |
|:---:|---|
| ● | MSX-DOS／MSX-DOS2 共通 |
| ◆ | MSX-DOS2 専用（DOS1 には存在しない） |
| ▲ | 共通だが、DOS2 で拡張または動作に差異がある |

サンプルプログラムはすべて Z80 アセンブリ言語（zma 記法）で書かれ、アセンブル済みの .COM とともにサンプル集として別途配布する。各サンプルには対象（●／◆）を明記した。

## 1.2 ファンクションコールとは ●

ファンクションコールは、プログラムが DOS カーネルの機能（ファイル入出力、コンソール入出力、日時、メモリ情報など）を呼び出すための窓口である。呼び出しはアドレス 0005h への CALL で行う。

```
		ld		c, 0x09			; ファンクション番号は C レジスタ
		ld		de, msg			; 引数はファンクションごとに決まったレジスタ
		call	0x0005			; 0005h を呼ぶ
```

- ファンクション番号は **C レジスタ**に入れる。
- 引数と戻り値は、ファンクションごとに決まったレジスタ（主に A、BC、DE、HL、IX）で受け渡す。各ファンクションの約束は第8章のリファレンスにまとめた。
- 0005h の実体はページ 0 に置かれたジャンプ命令で、カーネル本体（ディスク ROM 側にあり、DOS2 では初期化時にマッパー RAM へコピーされて実行される）へ中継する。プログラムはカーネルの置き場所を意識する必要はない。
- 呼び出しによって **AF、BC、DE、HL は破壊されうる**ものとして扱うのが安全である（保存される保証があるのは一部のレジスタのみで、ファンクションにより異なる）。IX、IY は多くのファンクションで入力に使うため、呼び出し側が値を保持したい場合は自分で退避する。

なお、同じ呼び出しはアドレス 0F37Dh からも行える（こちらがカーネルへの直接の入口で、DOS1／DOS2 に共通する）。通常のアプリケーションプログラムは 0005h を使えばよい。

## 1.3 プログラムの開始と終了 ●

.COM プログラムはアドレス 0100h から読み込まれ、0100h から実行が始まる。ページ 0 には DOS が用意した情報が並んでいる。

| アドレス | 内容 |
|---|---|
| 0000h | ウォームブートへのジャンプ（ここへジャンプすると DOS に戻る） |
| 0005h | ファンクションコールの入口 |
| 0006h〜0007h | TPA の上限アドレス（利用可能メモリの終端＋1 の下位） |
| 005Ch | デフォルト FCB #1（コマンドラインの第 1 引数から DOS が組み立てる） |
| 006Ch | デフォルト FCB #2（第 2 引数から組み立てる） |
| 0080h | コマンドラインの尾部（先頭 1 バイトが文字数、続いて文字列。DTA の初期値でもある） |

プログラムの終了方法は 3 通りある。

1. **ret**： .COM の初期スタックには戻り先として 0000h が積まれているため、先頭レベルの ret で DOS に戻れる。最も簡単で、小さなプログラムでは普通の方法である。
2. **_TERM0（00h）** ●： CP/M 以来の終了ファンクション。DOS1／DOS2 共通。
3. **_TERM（62h）** ◆： DOS2 の終了ファンクション。B レジスタに終了コードを渡せ、バッチファイルの ERRORLEVEL 判定や親プロセス（_FORK で起動した子など）に結果を伝えられる。DOS2 向けのプログラムではこちらが本命である。

DOS1 には終了コードの概念がない。DOS1／DOS2 両対応のプログラムは ret か _TERM0 で終了するのが無難である。

## 1.4 戻り値とエラーの返し方 ▲

成功・失敗の返し方は、DOS1 と DOS2 で流儀が異なる。本書全体を貫く最重要の違いなので、ここで整理する。

**DOS1 の流儀**： ファンクションごとにまちまちである。ファイル系（FCB 系）は **A=00h で成功、A=FFh で失敗**（オープンできない、ファイルが見つからない等）が基本で、シーケンシャル読み込みでは A=1 が「ファイル終端」を意味するなど、番号ごとに約束が決まっている。「なぜ失敗したか」は返らない。

**DOS2 の流儀**： DOS2 で新設されたファンクション（31h、40h〜70h）は、**A にエラーコードそのもの**が返る（A=0 が成功、0 以外はエラーコード）。多くの場合 B レジスタにも同じコードが入る。エラーコードは「ファイルが見つからない」「ディスクがいっぱい」など原因を区別でき、_EXPLAIN（66h）で人間が読める文字列に変換できる（5.5 節）。

**DOS2 上で FCB 系（DOS1 互換）ファンクションを使った場合**： 返却の流儀は互換形式が維持され、A=00h／FFh の約束で判定できる。本書の FCB サンプルは、成功が A=0、失敗が A≠0 という判定で DOS1／DOS2 の両方に対応している。

判定コードの書き分けの指針：

- DOS1／DOS2 共通のプログラム： FCB 系とコンソール系を使い、A=0 を成功として判定する。
- DOS2 専用のプログラム： ハンドル系を使い、A≠0 なら A のコードを _EXPLAIN に渡して表示する。

## 1.5 DOS の判別 ●

プログラムが DOS1 と DOS2 のどちらで動いているかは、起動後に判別できる。注意すべきは、**_CPMVER（0Ch）は判別に使えない**ことである。このファンクションは DOS1／DOS2 のどちらでも常に CP/M 2.2 相当（A=L=22h）を返す、互換性のための飾りである。

判別には **_DOSVER（6Fh）** ◆ を使う。仕様書が示す手順は次のとおりである。

1. _DOSVER を呼ぶ。
2. A≠0 なら、それは MSX-DOS ですらない環境（素の CP/M 等）である。
3. B（カーネルバージョンのメジャー）が 2 未満なら DOS1 系である。この場合 C と DE の内容は不定なので読んではいけない。
4. B が 2 以上なら DOS2 であり、BC にカーネルバージョン、DE に MSXDOS2.SYS のバージョンが BCD で返る。通常は DE 側（実際にプログラムと相対するシステムファイルの版）を確認する。

両対応プログラムの定石は、この判別で DOS2 ならハンドル系、DOS1 なら FCB 系へ分岐する、という構成である。サンプル集の envdemo.asm（7 章）は _DOSVER の実例になっている。

## 1.6 最初のプログラム

リスト 1-1 が、ファンクションコールだけを使った最小のプログラムである（サンプル集の hello.asm）。

リスト 1-1 hello.asm（●共通）

```
;=====================================================================
; hello.asm - 最小の MSX-DOS プログラム (第1章)
;
; ファンクションコールは 0005h を C=ファンクション番号 で呼ぶ。
; ここでは _STROUT (09h) で '$' 終端文字列を表示し、
; ret で DOS に戻る (.COM の終了は ret でもよい)。
;
; 対象: MSX-DOS / MSX-DOS2 共通
; ビルド: zma hello.asm -> HELLO.COM
;=====================================================================
		org		0x0100

BDOS	:= 0x0005

start::
		ld		de, msg
		ld		c, 0x09			; _STROUT: 文字列出力
		call	BDOS
		ret						; DOS へ戻る

msg:	db		"Hello, MSX-DOS!$"
```

動作は単純だが、要素はすべて詰まっている。org 0100h、C レジスタへの番号設定、DE への引数、0005h の CALL、そして ret による終了である。以後の章のサンプルは、すべてこの骨格の上に築かれる。

# 第2章 コンソール入出力

## 2.1 コンソールファンクションの一覧 ●

文字入出力のファンクションは DOS1／DOS2 共通である。DOS2 では標準入出力のリダイレクトの対象になる点が拡張されている（▲）。

| 番号 | 名前 | 記号 | 入力 | 出力 | 備考 |
|---|---|:---:|---|---|---|
| 01h | _CONIN | ▲ | - | A=入力文字 | エコーあり。DOS2 では標準入力ハンドル経由 |
| 02h | _CONOUT | ▲ | E=文字 | - | DOS2 では標準出力ハンドル経由（リダイレクト可） |
| 03h | _AUXIN | ● | - | A=入力文字 | 補助入力（AUX デバイス） |
| 04h | _AUXOUT | ● | E=文字 | - | 補助出力 |
| 05h | _LSTOUT | ● | E=文字 | - | プリンタ出力 |
| 06h | _DIRIO | ● | E=文字／FFh | A=入力文字（入力時） | エコー・制御検査なしの直接入出力 |
| 07h | _DIRIN | ● | - | A=入力文字 | エコーなし入力（制御検査もなし） |
| 08h | _INNOE | ● | - | A=入力文字 | エコーなし入力 |
| 09h | _STROUT | ● | DE='$' 終端文字列 | - | 文字列出力 |
| 0Ah | _BUFIN | ● | DE=入力バッファ | バッファに入力長と文字列 | 編集付き 1 行入力 |
| 0Bh | _CONST | ● | - | A=FFh（キーあり）／00h | コンソールステータス |

## 2.2 出力の基本 _STROUT と _CONOUT ●

文字列の表示は _STROUT（09h）が基本である。DE に文字列の先頭アドレスを入れると、'$'（24h）が現れるまで出力する。'$' 自体は表示できないので、'$' を含む文面や、長さの決まったデータを出す場合は _CONOUT（02h）で 1 文字ずつ出す。

制御文字はそのまま画面制御に効く（0Dh で行頭、0Ah で改行、08h でバックスペース等）。日本語（Shift_JIS）のバイト列もそのまま通る。DOS は文字コードの解釈をしないので、2 バイト文字の途中で表示が切れても DOS の側は関知しない。切り分けは表示側プログラムの責任である。

## 2.3 入力の基本 _CONIN、_INNOE、_DIRIN ●

1 文字入力には 3 種類ある。

- **_CONIN（01h）**： 入力した文字が画面にエコーされる。対話的な入力向き。
- **_INNOE（08h）**： エコーされない。パスワード的な入力や、表示を自分で制御したい場合に使う。
- **_DIRIN（07h）**： エコーも制御文字の検査もされない、最も素の入力。キー入力をそのままゲーム等で読みたい場合の候補だが、Ctrl-C による中断も効かなくなる点に注意。

いずれもキーが押されるまで戻らない（ブロッキング）。キー入力の有無だけを調べたい場合は _CONST（0Bh）を使う。_CONST や _CONIN 等のコンソール検査のタイミングで、Ctrl-C（中断）、Ctrl-P（プリンタエコー切替）、Ctrl-S（表示一時停止）等の特殊処理が発動する仕組みになっている。つまり、コンソール系ファンクションを一切呼ばないプログラムは Ctrl-C で止められない。

## 2.4 行入力 _BUFIN ●

行単位の入力は _BUFIN（0Ah）を使う。DE が指すバッファの形式は CP/M 以来のものである。

| オフセット | 内容 |
|---|---|
| +0 | バッファ容量（プログラムが最大文字数を入れておく） |
| +1 | 入力された文字数（DOS が返す） |
| +2〜 | 入力された文字列（末尾に CR は含まれない） |

入力中は行編集（バックスペース、行の消去等）が効く。DOS2 では過去に入力した行を呼び出す履歴機能（256 バイトの循環バッファ）も備わる。COMMAND2.COM のコマンド行入力もこのファンクションの上に作られている。

注意点として、+0 に容量を入れるのはプログラム側の責任である。ここが 0 だと 1 文字も入力できない。また入力文字列の直後には何も書かれない（終端の 0 は付かない）ので、文字列として扱う場合は +1 の文字数で範囲を決めるか、自分で終端を書き足す。

## 2.5 サンプル： 行入力とエコー

リスト 2-1 は _BUFIN で 1 行読み、_CONOUT で 1 文字ずつ表示し直すサンプルである（サンプル集の conio.asm、●共通）。DOS2 環境で、プロンプトから起動して行を入力し、入力内容がそのまま表示されることを対話操作で確認した。使うファンクションはすべて DOS1 と共通のものである。

リスト 2-1 conio.asm（抜粋）

```
		ld		de, inbuf
		ld		c, 0x0A			; _BUFIN: 編集付き 1 行入力
		call	BDOS
		; --- 入力内容を表示し直す ---
		ld		a, [inbuf + 1]	; 入力された文字数
		or		a, a
		jr		z, done
		ld		b, a
		ld		hl, inbuf + 2
echo_loop:
		ld		e, [hl]
		push	hl
		push	bc
		ld		c, 0x02			; _CONOUT: 1 文字出力 (E)
		call	BDOS
		pop		bc
		pop		hl
		inc		hl
		djnz	echo_loop
```

ファンクションコールはレジスタを壊すので、ループカウンタ（B）とポインタ（HL）を呼び出しの前後で退避している点に注目してほしい。これは本書の全サンプルに共通する作法である。

## 2.6 直接入出力 _DIRIO ●

_DIRIO（06h）は、E=FFh で入力（キーがなければ A=0、あれば A=文字）、それ以外で E の文字を出力する、エコーも制御検査もない直接入出力である。リアルタイムにキーを拾いたい処理で使われるが、Ctrl-C 中断も効かない。用途が明確な場合だけ使うのがよい。

# 第3章 FCB の構造と初期化 ●

## 3.1 FCB とは

FCB（File Control Block、ファイルコントロールブロック）は、ファイルを扱うための情報をまとめた、プログラム側のメモリ上の領域です。1つのファイルにつき1つの FCB を用意し、そのアドレスを DE レジスタに入れてファンクションコールを呼びます。

FCB の大きさは 37 バイトです。ただし先頭の 33 バイトが基本部で、末尾の 4 バイトはランダムアクセス用のランダムレコード番号です。シーケンシャルアクセスだけなら 33 バイトで足りますが、実務では常に 37 バイト確保しておくのが安全です。

FCB を使うファンクションはすべて DOS1／DOS2 共通（●）で、DOS2 上でもそのまま動作します。ただし注意点が1つあります。**オフセット 12〜15 と 20〜31 の領域は、DOS1 と DOS2 で解釈が違います。** 同じメモリを、DOS1 は「カレントブロック／レコードサイズ／日付・時刻／クラスタ情報」として、DOS2 は「エクステント番号／属性／ボリューム ID／内部情報」として扱います。本章では DOS1 の見方を主表とし、DOS2 の見方を対照表で示します。どちらの環境で動かすプログラムでも、プログラムが自分で読み書きしてよいフィールドは共通しているので、使い分けは難しくありません。

## 3.2 全フィールド表（DOS1 の見方）

オフセットは FCB 先頭からのバイト数です。多バイト数値はすべて下位バイト先行（リトルエンディアン）で格納されます。「設定者」欄は、そのフィールドを主に誰が書くかを示します。

| オフセット（10進） | オフセット（16進） | サイズ | 名称 | 意味 | 設定者 |
|---:|---:|---:|---|---|---|
| 0 | 00h | 1 | ドライブ番号 | ファイルのあるドライブ。0＝デフォルトドライブ、1＝A:、2＝B:、…、8＝H: | プログラム |
| 1 | 01h | 8 | ファイル名 | 最大8文字。不足分はスペース（20h）で埋める。検索系では "?" が任意の1文字 | プログラム |
| 9 | 09h | 3 | 拡張子 | 最大3文字。不足分はスペース（20h）で埋める | プログラム |
| 12 | 0Ch | 2 | カレントブロック | シーケンシャルアクセスで参照中のブロック番号 | プログラムが初期化／DOS が更新 |
| 14 | 0Eh | 2 | レコードサイズ | ランダムブロックアクセス（_RDBLK／_WRBLK）で使う1レコードのバイト数（1〜65535） | プログラム（オープン後） |
| 16 | 10h | 4 | ファイルサイズ | ファイルの大きさ（バイト単位の正確な値） | DOS |
| 20 | 14h | 2 | 日付 | 最後に書き込んだ日付（ディレクトリエントリと同じ形式） | DOS |
| 22 | 16h | 2 | 時刻 | 最後に書き込んだ時刻（同上） | DOS |
| 24 | 18h | 1 | デバイス ID | ディスクファイルは 40h＋ドライブ番号。デバイスは CON＝FFh、PRN＝FBh、LST＝FCh、NUL＝FDh、AUX＝FEh。プログラムは使わないこと | DOS |
| 25 | 19h | 1 | ディレクトリロケーション | そのファイルが何番目のディレクトリエントリか | DOS |
| 26 | 1Ah | 2 | 先頭クラスタ | ファイルの先頭クラスタ番号 | DOS |
| 28 | 1Ch | 2 | 最終クラスタ | 最後にアクセスされたクラスタ番号 | DOS |
| 30 | 1Eh | 2 | 相対位置 | 最後にアクセスされたクラスタの先頭からの相対位置 | DOS |
| 32 | 20h | 1 | カレントレコード | シーケンシャルアクセスで参照中のレコード番号（0〜127） | プログラムが初期化／DOS が更新 |
| 33 | 21h | 4 | ランダムレコード番号 | ランダム／ブロックアクセスでアクセスするレコード番号 | プログラム／DOS が更新 |

日付・時刻のビット形式は、年（1980年からの差）・月・日、時・分・秒÷2 を詰めたもので、ディレクトリエントリや DOS2 のファイル時刻（第6章）と共通です。

## 3.3 DOS2 での同じ領域の見方

DOS2 の Program Interface Specification は、同じ領域を次のように定義しています。DOS2 環境で FCB の中身を解釈するとき（デバッグ時など）はこちらが正です。

| オフセット（16進） | サイズ | DOS2 での意味 | 備考 |
|---:|---:|---|---|
| 00h | 1 | ドライブ番号（1〜8、0＝デフォルト）。全ての FCB でプログラムが設定する。DOS は原則変更しない | |
| 01h〜08h | 8 | ファイル名。左詰め・末尾スペース。あいまい指定可の関数では "?" 可。比較は大小区別なし。新規作成時は大文字化される | |
| 09h〜0Bh | 3 | 拡張子。CP/M と違い bit7 はフラグとして解釈されない | |
| 0Ch | 1 | エクステント番号（下位）。**オープン／作成の前にプログラムが設定する（通常0）** | DOS1 の見方のカレントブロック下位バイト |
| 0Dh | 1 | ファイル属性。オープン／作成／検索が設定する | DOS1 の見方ではカレントブロック上位バイト |
| 0Eh | 1 | エクステント番号（上位）。オープン／作成で 0 にされる。ブロック系ではレコードサイズの下位バイト（併用定義） | |
| 0Fh | 1 | レコードカウント。オープン／作成で設定される。ブロック系ではレコードサイズの上位バイト（併用定義） | |
| 10h〜13h | 4 | ファイルサイズ（正確なバイト数）。**クローズ時にディスクへ書き戻されるので変更禁止** | |
| 14h〜17h | 4 | ボリューム ID。オープン／作成で設定され、読み書き・クローズ時に照合される。**変更禁止** | DOS1 が日付・時刻を置く場所 |
| 18h〜1Fh | 8 | 内部情報。**プログラムは一切変更してはならない** | DOS1 の内部情報とも内容は異なる |
| 20h | 1 | カレントレコード（0〜127）。**最初のシーケンシャル読み書きの前にプログラムが設定する（通常0）** | |
| 21h〜24h | 4 | ランダムレコード番号。ランダム／ブロック系を使う前にプログラムが設定する | |

2つの見方で実務上重要なのは、次の3点です。

- DOS1 の「レコードサイズ」（+14〜+15）は、DOS2 では「エクステント上位＋レコードカウント」と「レコードサイズ」の併用定義です。オープン直後にこの2バイトをレコードサイズとして読むと無意味な値になります（3.6節）。
- DOS1 の「日付・時刻」（+20〜+23）は、DOS2 ではボリューム ID です。DOS2 上で FCB から更新日時を読もうとしても読めません。DOS2 で日時が要る場合は _FTIME（51h）や FIB を使います。
- どちらの見方でも、+16〜+31 はオープン後に DOS の管理領域であり、プログラムが書き換えてはなりません。

## 3.4 オープン前の必須初期化

FCB を扱うプログラムで最も多い失敗が、「ファイルがあるのにオープンできない」です。その大半は、FCB の初期化不足が原因です。ここでは ASCII の仕様書（MSX-DOS 2 Function Specification および Program Interface Specification）の明文に基づいて、プログラムが設定しなければならないフィールドを整理します。

まず結論です。**オープン（_FOPEN）／作成（_FMAKE）を呼ぶ前に、プログラムが必ず書くものは次の4点です。**

| オフセット | フィールド | 設定値 |
|---:|---|---|
| +0（00h） | ドライブ番号 | 0＝デフォルトドライブ、または 1＝A: … 8＝H: |
| +1〜+8（01h〜08h） | ファイル名 | 左詰め、不足分はスペース（20h）で埋める |
| +9〜+11（09h〜0Bh） | 拡張子 | 左詰め、不足分はスペース（20h）で埋める |
| +12（0Ch） | エクステント下位（カレントブロック下位） | 通常 0 |

仕様書は「FCB の残り全部がゼロでなければならない」とは書いていません。その代わり、フィールドごとに「誰がいつ設定するか」を明記しています。中でも +12 は「**オープン／作成の前に、プログラムが（通常はゼロに）設定しなければならない**」と強く書かれているフィールドです。ここにゴミが入っていると、次のような症状になります。

- _FOPEN： エクステントはオープンでは変更されません。指定したエクステントを含む大きさのファイルでなければ開けないため、**実在するファイルでも「見つからない」（A＝FFh）** になります。
- _FMAKE： エクステントが非ゼロだと、既存ファイルは切り捨て・新規作成されず、**そのまま開かれるだけ** になります。新規作成したつもりで古い内容が残る、という事故になります。

実務上の結論として、本書のサンプルはすべて「**FCB 領域 37 バイトを全部ゼロクリアしてから、ドライブ番号とファイル名・拡張子だけを書き込む**」という手順を取っています。これで +12 のゼロ化を含め、仕様書が要求する事前条件をすべて満たせます。なお DOS1 向けの解説（MSX Wiki の FCB の項）には「ドライブ、ファイル名、拡張子を指定し、残りは少なくともレコードカウント（+15）までは 0 にしておくこと」という、より強い形の規則もあります。ゼロクリア方式はこの規則も同時に満たします。

逆に、オープン成功後に FCB をゼロクリアし直してはいけません。+16〜+31 は DOS が設定した領域で、書き換えると読み書きやクローズが正しく動かなくなります。

### オープン成功後に、読み書きの前に設定するもの

オープン／作成は、次のフィールドを設定しません。これらは「使う前」にプログラム自身が設定するものです。

| オフセット | フィールド | タイミングと値 |
|---:|---|---|
| +32（20h） | カレントレコード | 最初のシーケンシャル読み書きの前に、通常 0。オープンでは変更されないので、ゴミが残っていると途中から読み書きが始まる |
| +33〜+36（21h〜24h） | ランダムレコード番号 | ランダム／ブロック読み書きの前に、アクセスしたいレコード番号 |
| +14〜+15（0Eh〜0Fh） | レコードサイズ | オープンの**後**、_RDBLK／_WRBLK を呼ぶ前に（3.6節） |

カレントレコードについては、仕様書の _FOPEN の項が「カレントレコードとランダムレコードはこの関数では変更されない。それらを使う読み書きの前に初期化するのはアプリケーションプログラムの責任である」と明記しています。「オープンしたのに途中から読まれる」という症状は、ほぼこの初期化忘れです。

## 3.5 ファイル名の書き方

- ファイル名は左詰めで、8文字に満たない分はスペース（20h）で埋めます。拡張子も同様に3文字まででスペース埋めします。ピリオドや終端文字（00h）は入れません。
- 大文字小文字は、DOS2 では比較の際に区別されません。新規作成時には名前が大文字化されます。また _FOPEN は、FCB 内の名前を実際に開いたファイルのディレクトリエントリ上の名前で置き換えます（あいまい指定で開いた場合、戻ってきた名前が入力と異なることがあります）。それでも本書のサンプルは、DOS1 での確実さも考えて大文字＋スペース埋めで統一しています。
- あいまい指定 "?"（3Fh）は、オープン、検索、削除などで使えます。作成では使えません。ファンクションコールレベルでは "*" はサポートされず、必要な数だけ "?" に置き換えて指定します。
- デバイス名（CON、PRN、LST、NUL、AUX）も FCB で指定できます。コロンは付けず、ファイル名の位置に置きます。

## 3.6 レコードサイズを設定するタイミング

レコードサイズ（+14〜+15）が関係するのは、ランダムブロック読み書き（_WRBLK 26h／_RDBLK 27h）だけです。シーケンシャル読み書き（14h／15h）とランダム読み書き（21h／22h）は、レコードサイズフィールドを使わず、常に 128 バイト単位で転送します。

そして重要なのはタイミングです。**レコードサイズは、オープンの前に設定しても意味がありません。** DOS2 の仕様では、オープンは +14 に 0（エクステント上位）を、+15 にレコードカウントを設定します。つまりオープン直後の +14〜+15 は、レコードサイズとして読むと無意味な値です。仕様書の _WRBLK の項は「レコードサイズフィールドは、**ファイルを開いた後、この関数を呼ぶ前に**ユーザーが設定しなければならない」と時期まで明記しています。

手順は次のとおりです（ランダムブロックで 128 バイト以外のレコードサイズを使う場合）。

1. FCB をゼロクリアし、ドライブ＋ファイル名＋拡張子を設定する（+12 は 0 のまま）
2. _FOPEN または _FMAKE を呼ぶ
3. 成功後、+14〜+15 にレコードサイズ、+33〜+36 に開始ランダムレコード番号を設定する
4. _SETDTA で転送先を設定し、HL＝レコード数で _RDBLK／_WRBLK を呼ぶ

「オープンすると DOS がレコードサイズに 128 を入れてくれる」という説明を目にすることがありますが、調べた MSX の仕様書にその記述はありません（PC の MS-DOS の FCB の説明と混同されやすい点です）。128 バイトで使う場合も含め、ブロック系を使うなら自分で書き込むのが仕様上の正しい手順です。

## 3.7 DTA の設定

FCB 系の読み書きと検索は、転送先アドレスとして DTA（Disk Transfer Address）を使います。_SETDTA（1Ah）で DE にアドレスを入れて設定します。

- DTA の初期値は 0080h です。0080h はコマンドライン文字列（長さバイト＋本体）が置かれる場所でもあるので、引数解析が済む前に FCB 読み書きをすると、コマンドラインを上書きします。
- _DSKRST（0Dh）を呼ぶと DTA は 0080h に戻されます。
- 転送量は、シーケンシャル／ランダム読み書きが 1 回 128 バイト固定、ブロック系が「レコードサイズ×レコード数」バイトです。DTA の先に十分な領域を確保してください。
- DOS2 のハンドル系ファンクションは DTA を使いません（アドレスをレジスタで直接渡します。第5章）。

## 3.8 ページゼロのデフォルト FCB の罠

ページゼロの 005Ch と 006Ch には、コマンドライン引数から DOS が組み立てた FCB が置かれています。便利ですが、この2つは先頭が 16 バイトしか離れていないため、**片方をオープンすると、DOS が書き込む管理領域でもう片方が上書きされます**。両方の引数ファイルを同時に開く場合は、片方を別の場所へコピーしてから開いてください。また、デフォルト FCB の +12 以降は DOS が保証する初期化の対象ではないので、3.4節の手順どおり、使う前に必要なフィールドを確認・設定することが大切です。

## 3.9 CP/M の FCB との違い

MSX-DOS の FCB は CP/M の FCB を拡張したものです。主な違いを挙げます。

| 項目 | CP/M 2.2 | MSX-DOS |
|---|---|---|
| 全長 | 36 バイト | 37 バイト（ランダムレコード最大4バイト）。基本部は 33 バイト |
| +12〜+15 | エクステント番号、予約、レコードカウント（各1バイト） | DOS1 の見方ではカレントブロック（2バイト）とレコードサイズ（2バイト）に組み替え。DOS2 の見方は 3.3節 |
| +16〜+31 | アロケーションマップ | ファイルサイズ、日付・時刻、デバイス ID、クラスタ情報などに流用（DOS2 ではボリューム ID＋内部情報） |
| レコードサイズ | 概念なし（128バイト固定） | ブロック系でのみ任意（1〜65535）。MSX-DOS 独自の拡張 |
| ファイルサイズ | バイト単位の欄なし | +16〜+19 に正確なバイト数。128バイト未満の端数がありうる |
| 拡張子の bit7 | フラグとして解釈される場合がある | 解釈されない |

# 第4章 FCB の使い方 ●

本章では FCB を使うファンクション群を、アクセス方式ごとに解説します。すべて DOS1／DOS2 共通（●）です。呼び出しの共通作法は第1章、FCB の初期化は第3章を前提とします。

FCB 系ファンクションの戻り値は旧方式（第1章）で、成功は A＝00h、失敗はファンクションによって A＝FFh（見つからない／不成功）または A＝01h（EOF／ディスクフルなど）です。DOS2 上では、失敗の本当の原因を _ERROR（65h）でエラーコードとして取得できます（第7章）。

## 4.1 作成とオープン

| 番号 | 名前 | 入力 | 出力 | 用途 |
|---:|---|---|---|---|
| 16h | _FMAKE | DE＝FCB | A＝00h 成功／FFh 失敗 | ファイルを新規作成する（既存なら切り捨て） |
| 0Fh | _FOPEN | DE＝FCB | A＝00h 成功／FFh 失敗 | 既存ファイルを開く |
| 10h | _FCLOSE | DE＝FCB | A＝00h 成功／FFh 失敗 | 閉じる（サイズ・日時を書き戻す） |

_FMAKE と _FOPEN の使い方は第3章の初期化手順どおりです。どちらも、成功すると FCB の管理領域（ファイルサイズ、DOS2 ではボリューム ID と内部情報など）を DOS が設定します。失敗は A＝FFh で判定します。

_FOPEN には DOS2 での拡張があります（▲）。ファイルが見つからない場合、環境アイテム APPEND の指すディレクトリも検索されます。また、サブディレクトリとシステムファイルは _FOPEN では開けません。

クローズは省略できません。書き込んだデータのディスクへの反映や、ファイルサイズ・日時の書き戻しは _FCLOSE で行われます。書き込み後にクローズし忘れると、データが失われたり、サイズが古いまま残ったりします。

## 4.2 シーケンシャル読み書き

| 番号 | 名前 | 入力 | 出力 |
|---:|---|---|---|
| 14h | _RDSEQ | DE＝FCB | A＝00h 成功／01h EOF またはエラー |
| 15h | _WRSEQ | DE＝FCB | A＝00h 成功／01h ディスクフル等 |
| 28h | _WRZER | DE＝FCB | A＝00h 成功／01h エラー |

シーケンシャル読み書きは、DTA との間で **128 バイト固定** で転送します。転送位置は FCB のエクステント（+12）とカレントレコード（+32）が保持し、呼び出しごとに自動で進みます。ファイル内位置は「エクステント番号×16384＋カレントレコード×128」で決まります。

- 読み出しでファイルの終端に達すると A＝01h になります。最終レコードが 128 バイト未満の場合、そのレコードは読み出せて（A＝00h）、足りない分はゼロで埋められます。次の読み出しで A＝01h になります。テキストファイルのコピーのような処理では、「A＝01h になるまで繰り返す」のが基本形です（サンプル FCBCOPY）。
- 書き込みは常に 128 バイト単位です。テキストを 1 レコード分だけ書く場合、残りは 1Ah（EOF 文字）で埋めるのが慣例です（サンプル FCBMAKE）。128 バイトに満たないファイルを正確なサイズで作りたい場合は、ブロック系（4.4節）かハンドル系（第5章）を使います。
- _WRZER は _WRSEQ と似ていますが、ランダムレコード番号で指定した位置へ、間をゼロで埋めながら書き込みます。

## 4.3 ランダム読み書き

| 番号 | 名前 | 入力 | 出力 |
|---:|---|---|---|
| 21h | _RDRND | DE＝FCB | A＝00h 成功／01h EOF またはエラー |
| 22h | _WRRND | DE＝FCB | A＝00h 成功／01h エラー |
| 24h | _SETRND | DE＝FCB | なし |

ランダム読み書きは、FCB のランダムレコード番号（+33〜+36 の下位 3 バイト）が指すレコードへ、DTA との間で **128 バイト固定** で転送します。レコードサイズフィールド（+14）は使いません。転送位置は「ランダムレコード番号×128」です。

- ランダム読み書きはランダムレコード番号を**自動で進めません**。連続して読み書きしたい場合は、毎回プログラムが番号を設定します。
- _SETRND は、現在のエクステントとカレントレコードからランダムレコード番号を計算して FCB に設定します。シーケンシャルで途中まで読んだ位置からランダムアクセスへ切り替えるときに使います。
- レコードサイズを 128 バイト以外にしたい場合は、ランダム読み書きではなく次のブロック系を使います。ここは混同しやすい点で、4.6節に実測例を示します。

## 4.4 ランダムブロック読み書き

| 番号 | 名前 | 入力 | 出力 |
|---:|---|---|---|
| 26h | _WRBLK | DE＝FCB、HL＝レコード数 | A＝00h 成功／01h エラー |
| 27h | _RDBLK | DE＝FCB、HL＝レコード数 | A＝00h 成功／01h エラー、HL＝実際に読んだレコード数 |

ブロック系は、レコードサイズ（+14〜+15、オープンの後に設定）×レコード数（HL）のバイト数を、DTA との間で一括転送します。ランダムレコード番号は呼び出しごとに自動で進みます（読み出しでは実際に読んだ数だけ、書き込みでは要求した数だけ進みます）。

読み出しと書き込みで、HL の戻り値の扱いが非対称な点に注意してください。

- _RDBLK は、実際に読み出したレコード数を HL に返します。ファイル終端に達すると要求より小さくなり、そのとき A＝01h です。端数の部分レコードはゼロ埋めされて DTA にコピーされます。
- _WRBLK は、HL に実レコード数を返しません（文書化されていません）。成否は A だけで判定します。
- 1回の転送は 64KB を超えるとエラーになります（レコードサイズ×レコード数 ≦ 65535 が目安です）。
- _WRBLK で HL＝0 を指定すると、データ転送は行われず、**ファイルサイズがランダムレコード位置に合わせて変更されます**（切り捨て／拡張の両方。拡張部分の内容は不定）。ファイルの切り捨てに使える特殊動作です。

## 4.5 検索・削除・名前変更

| 番号 | 名前 | 入力 | 出力・備考 |
|---:|---|---|---|
| 11h | _SFIRST | DE＝未オープン FCB（"?" 使用可） | A＝00h 見つかった／FFh なし。DTA に「ドライブ番号＋ディレクトリエントリ 32 バイト」が入る |
| 12h | _SNEXT | DE＝_SFIRST で使った FCB | 同上。次の候補を探す |
| 13h | _FDEL | DE＝FCB（"?" 使用可） | A＝00h 成功／FFh 失敗。該当ファイルをすべて削除 |
| 17h | _FREN | DE＝リネーム用 FCB | A＝00h 成功／FFh 失敗。FCB+17 に新しい名前（ドライブ＋名前＋拡張子）を置く |
| 23h | _FSIZE | DE＝FCB | ランダムレコード番号にファイルのレコード数が設定される |

_SFIRST が見つけた場合、DTA の内容はそのまま「未オープン FCB」として _FOPEN に渡せます。サンプル DIRLIST は、_SFIRST／_SNEXT で得たエントリから名前を取り出して一覧ファイルを作ります。

_FREN の FCB は特殊な形です。先頭に旧名の FCB（ドライブ＋名前＋拡張子）を置き、+17 の位置に新しい名前（ドライブ番号 1 バイト＋名前 8 バイト＋拡張子 3 バイト）を置きます。DOS2 ではハンドル系の _RENAME（4Eh、文字列で指定）もあるので、新規のプログラムではそちらが簡単です（第6章）。

ディスクの空き容量は _ALLOC（1Bh）で調べます。入力は E＝ドライブ番号（0＝カレント、1＝A: …）で、A＝クラスタあたりセクタ数、BC＝セクタサイズ（常に512）、DE＝全クラスタ数、HL＝空きクラスタ数、IX＝DPB へのポインタ、IY＝最初の FAT セクタへのポインタが返ります（サンプル ALLOC がこの形で表示します）。DOS2 では IY から読めるのは FAT の第1セクタのみで、次の DOS コールまでしか有効でない点が DOS1 と異なります（▲）。

## 4.6 実測で分かった落とし穴： ランダム読み書きとレコードサイズ

本書のサンプル FCBRAND の初版は、「レコードサイズ 16 バイトを FCB+14 に設定し、_WRRND で 4 レコード書けば 64 バイトのファイルができる」という想定で書かれていました。実機（エミュレータ）で動かすと、できた RAND.BIN は **98,432 バイト** でした。

原因は2つの勘違いの重なりです。

1. _WRRND／_RDRND はレコードサイズフィールドを使わず、128 バイト固定です（4.3節）。レコードサイズが効くのはブロック系だけです。
2. ランダムレコード番号の置き場所は +33 からです。初版は +34 から書いていたため、番号が 256 倍（1バイトずれた値）として解釈されました。

128 バイト×（3×256＋1）＝98,432 バイトという計算が、できあがったファイルサイズと一致しました。仕様書を読み直してブロック系（_WRBLK／_RDBLK、レコードサイズはオープンの後に設定）に書き換えた版が、本書に掲載する FCBRAND です。仕様書の記述と実測が一致することを確認してから掲載する、という本書の方針を象徴する事例なので、あえて残しておきます。

## 4.7 サンプル： FCBMAKE（ファイル作成とシーケンシャル書き込み）

FCB を使った最も基本的な処理である。FCB 全体をゼロクリアしてから名前を書き、_SETDTA で転送先を設定し、_FMAKE で作成、_WRSEQ で 1 レコード（128 バイト）書き、_FCLOSE で閉じる。第3章の必須初期化の手順をそのまま実行している。DOS1／DOS2 両環境で動作確認済みで、TEST1.TXT（128 バイト）が作成される。

リスト 4-1 fcbmake.asm

```
;=====================================================================
; fcbmake.asm - FCB によるファイル作成とシーケンシャル書き込み (第3/4章)
;
; 本書の要点である「FCB の必須初期化」をそのまま実行するサンプル。
;   1. FCB 全体をゼロクリアする
;   2. ドライブ番号 (0=デフォルト) とファイル名 (空白パディング、
;      大文字) を設定する
;   3. DTA を自前のバッファに設定する (_SETDTA)
;   4. _FMAKE で作成し、_WRSEQ で 128 バイトレコードを 1 本書く
;   5. _FCLOSE で閉じる (閉じないとディレクトリが更新されない)
;
; 書き込むレコードは、本文の後に 1Ah (CP/M 以来の EOF) で埋める。
; FCB のレコードは固定長であり、テキストファイルでもこの埋め草が
; 実務上の作法になる。
;
; 対象: MSX-DOS / MSX-DOS2 共通
; ビルド: zma fcbmake.asm -> FCBMAKE.COM
; 結果: TEST1.TXT (128 バイト) が作成される
;=====================================================================
		org		0x0100

BDOS	:= 0x0005

start::
		; --- (1) FCB をゼロクリア ---
		ld		hl, fcb
		ld		b, 37
		xor		a, a
fcb_z:	ld		[hl], a
		inc		hl
		djnz	fcb_z
		; --- (2) ドライブとファイル名 ---
		; fcb+0 のドライブ番号は 0 のまま = カレントドライブ
		ld		hl, fname
		ld		de, fcb + 1
		ld		bc, 11
		ldir
		; --- (3) DTA を設定 ---
		ld		de, dta
		ld		c, 0x1A			; _SETDTA
		call	BDOS
		; --- レコードを用意: 本文 + 1Ah 埋め ---
		ld		hl, rectext
		ld		de, dta
		ld		bc, rectext_end - rectext
		ldir
		ld		hl, dta + (rectext_end - rectext)
		ld		b, 128 - (rectext_end - rectext)
		ld		a, 0x1A
rec_f:	ld		[hl], a
		inc		hl
		djnz	rec_f
		; --- (4) 作成 ---
		ld		de, fcb
		ld		c, 0x16			; _FMAKE
		call	BDOS
		or		a, a
		jp		nz, err_make
		; --- シーケンシャル書き込み (1 レコード) ---
		ld		de, fcb
		ld		c, 0x15			; _WRSEQ
		call	BDOS
		or		a, a
		jp		nz, err_write
		; --- (5) 閉じる ---
		ld		de, fcb
		ld		c, 0x10			; _FCLOSE
		call	BDOS
		or		a, a
		jp		nz, err_close
		ld		de, msg_ok
		ld		c, 0x09
		call	BDOS
		ret

err_make:
		ld		de, msg_emake
		jr		err_out
err_write:
		ld		de, msg_ewrite
		jr		err_out
err_close:
		ld		de, msg_eclose
err_out:
		ld		c, 0x09
		call	BDOS
		ret

msg_ok:		db	"TEST1.TXT created (128 bytes).", 0x0D, 0x0A, "$"
msg_emake:	db	"ERROR: _FMAKE failed.", 0x0D, 0x0A, "$"
msg_ewrite:	db	"ERROR: _WRSEQ failed.", 0x0D, 0x0A, "$"
msg_eclose:	db	"ERROR: _FCLOSE failed.", 0x0D, 0x0A, "$"

fname:	db		"TEST1   TXT"	; 8+3、空白パディング、大文字

rectext:	db	"FCBMAKE: this file was created by FCB sequential write.", 0x0D, 0x0A
rectext_end:

fcb:	space	37				; FCB 本体 (37 バイト)
dta:	space	128				; レコードバッファ (DTA)
```

## 4.8 サンプル： FCBRAND（ランダムブロック読み書き）

レコードサイズ 16 バイトで 4 レコードを _WRBLK で書き、レコード 2 を _RDBLK で読み戻すサンプルである。要点は、レコードサイズを _FMAKE の**後**に設定することと、ランダムレコード番号が FCB+33 から始まることである。DOS1／DOS2 両環境で動作確認済み（RAND.BIN は 64 バイトになる）。

リスト 4-2 fcbrand.asm（抜粋）

```asm
        ld      c, _FMAKE
        ld      de, fcb1
        call    BDOS
        or      a
        jp      nz, error

        ; --- Now set the record size (16) at FCB+14.
        ld      hl, 16
        ld      [fcb1 + 14], hl

        ld      c, _SETDTA
        ld      de, recbuf
        call    BDOS

        ; --- Write records 0..3.
wloop:
        ; random record number at FCB+33 (4 bytes)
        ld      a, [recno]
        ld      [fcb1 + 33], a
        xor     a
        ld      [fcb1 + 34], a
        ld      [fcb1 + 35], a
        ld      [fcb1 + 36], a
        ld      c, _WRBLK
        ld      de, fcb1
        ld      hl, 1                   ; 1 record
        call    BDOS
```

その他の FCB サンプルとして、FCBCOPY（_RDSEQ／_WRSEQ のループで TEST1.TXT を COPY.TXT へ複写）、DIRLIST（_SFIRST／_SNEXT でディレクトリ一覧を DIR.TXT に出力）、ALLOC（_ALLOC でディスク容量表示）をサンプル集に収録しています。いずれも DOS1／DOS2 両環境で動作確認済みです。

# 第5章 ファイルハンドル ◆

## 5.1 ハンドルとは ◆

DOS2 では、ファイル操作の中心は FCB から**ファイルハンドル**に移った。ハンドルは、開いたファイルを指す小さな整数（バイト値）である。プログラムはパス名でファイルを開いてハンドルを受け取り、以後の読み書きはハンドル番号で対象を指定する。

FCB 方式との違いを整理すると：

| 観点 | FCB ● | ハンドル ◆ |
|---|---|---|
| 対象の指定 | FCB のメモリブロック（37 バイト）を DE で指す | ハンドル番号を B に入れる |
| 名前の形式 | 8+3 形式、空白パディング、大文字、ドライブ番号 | パス名（ASCIIZ）。サブディレクトリ・ドライブ名・デバイス名可 |
| 入出力単位 | レコード（固定長）＋DTA | バイト数指定（HL）で任意長 |
| 位置の管理 | カレントブロック／レコード、ランダムレコード番号 | ファイルポインタ（_SEEK で移動） |
| エラー | A=00h／FFh（理由は分からない） | A=エラーコード（理由が分かる） |
| 同時オープン | FCB を自分で用意すれば複数可 | ハンドル表の範囲で複数可 |

ハンドル方式では、レコードサイズや DTA といった概念が消え、「開く→読む／書く→閉じる」がバイトストリームとして素直に書ける。本書の FCB 章（3・4 章）の知識は DOS1 互換のために必要だが、DOS2 専用でよいプログラムは原則ハンドルで書くのが現代的な作法である。

## 5.2 開く・作る ◆

| 番号 | 名前 | 入力 | 出力 |
|---|---|---|---|
| 43h | _OPEN | DE=パス名（ASCIIZ）または FIB、A=オープンモード | A=エラーコード、B=ハンドル |
| 44h | _CREATE | DE=パス名または FIB、A=オープンモード、B=作成属性（b7=新規作成フラグ） | A=エラーコード、B=ハンドル |

オープンモード（A）はビット指定である。

| ビット | 意味（セット時） |
|---|---|
| b0 | 書き込み禁止（読み専用で開く） |
| b1 | 読み出し禁止（書き込み専用で開く） |
| b2 | ハンドルの継承可（_FORK した子プロセスに引き継ぐ） |
| b3〜b7 | 必ず 0 |

_CREATE は、ファイルが存在すれば切り捨て（サイズ 0）にして開き、存在しなければ作って開く。B の b7（新規作成フラグ）を立てると、存在する場合はエラー（.EXIST）になる「作れる時だけ作る」動作になる。作成されるファイルには常に archive 属性が付く。

対象はパス名文字列のほか、FIB（ファイル情報ブロック、6 章）のポインタでも指定できる。CON、NUL、PRN 等のデバイスもパス名で開ける。デバイスは開いた直後は ASCII モードであり、_IOCTL（4Bh）でバイナリモードに切り替える（5.6 節）。

## 5.3 読む・書く ◆

| 番号 | 名前 | 入力 | 出力 |
|---|---|---|---|
| 48h | _READ | B=ハンドル、DE=バッファ、HL=読みたいバイト数 | A=エラーコード、HL=実際に読めたバイト数 |
| 49h | _WRITE | B=ハンドル、DE=バッファ、HL=書きたいバイト数 | A=エラーコード、HL=実際に書けたバイト数 |

実務上の要点：

- _READ は、要求より少なく読めることが正常に起こる（ファイル終端付近、デバイスからの入力など）。エラーではないので、HL の戻り値を見て、必要なら続けて読む。**0 バイト読めた時だけが終端（.EOF）**である。
- _WRITE は、ディスク不足の場合に中途半端に書くのではなく、エラー（.DKFUL）となり何も書かれない。戻り HL の確認は、デバイスへの書き込み等で意味を持つ。
- 大きなブロックでまとめて読み書きする方が効率がよい。1 バイトずつの _READ／_WRITE は、ファンクションコールの往復が支配的になり遅い。

## 5.4 位置を動かす _SEEK ◆

_SEEK（4Ah）はファイルポインタを移動する。入力は B=ハンドル、A=方式（0=先頭から、1=現在位置から、2=末尾から）、DEHL=符号付き 32 ビットオフセット。新しいファイルポインタが DEHL に返る。

応用： 方式 1・オフセット 0 で現在位置の取得、方式 2・オフセット 0 でファイルサイズの取得ができる。終端より先にポインタを置くことも許されており、その位置に書くと間はゼロで埋まる（ディスク上の実体は実装依存）。

## 5.5 閉じる・確実に書く ◆

| 番号 | 名前 | 役割 |
|---|---|---|
| 45h | _CLOSE | 閉じる。書き込んだ場合はディレクトリ更新とバッファのフラッシュが行われる |
| 46h | _ENSURE | 閉じずに、ディレクトリ更新とフラッシュだけを行う |
| 47h | _DUP | ハンドルを複製する（ファイルポインタを共有する新しいハンドル） |

DOS2 のディスクバッファは遅延書き込みであり、作成・書き込み・削除等の操作は自動ではフラッシュされないのが原則である。確実にディスクへ反映されるのは _CLOSE、_ENSURE、_FLUSH（5Fh）のタイミングである。電源断やリセットがありうる環境では、重要な区切りで _ENSURE を挟むのが実務的な配慮になる。

標準ハンドル（0=標準入力、1=標準出力、2=標準エラー出力、3=補助入出力、4=プリンタ）はプログラム起動時に DOS が用意しており、閉じずに使うのが普通である。標準入出力を _DUP で複製しておいてから付け替える、というのがリダイレクトを自前で実装する際の古典的な手順である。

## 5.6 エラーと _EXPLAIN ◆

ハンドル系を含む DOS2 のファンクションは、失敗時に A へエラーコードを返す。コードは _EXPLAIN（66h）で説明文字列に変換できる。入力は B=エラーコード、DE=文字列バッファで、バッファに ASCIIZ の説明が書かれる。

```
		ld		b, a			; A のエラーコードを B へ
		ld		de, errbuf
		ld		c, 0x66			; _EXPLAIN
		call	BDOS
```

エラーコードの一覧は付録 A にまとめた。代表的なものは .NOFIL（ファイルなし）、.NODIR（ディレクトリなし）、.DKFUL（ディスク満杯）、.WPROT（書き込み保護）、.EOF（ファイル終端）などである。なお _EXPLAIN の説明文は、DOS の言語設定により英語または日本語で返る。

## 5.7 サンプル： 作成と書き込み

リスト 5-1 は hmake.asm（◆）の中心部である。_CREATE → _WRITE → _CLOSE の最小構成で、書き込みバイト数の照合まで行っている。

リスト 5-1 hmake.asm（抜粋）

```
		; --- 作成 (既存があれば切り捨て) ---
		ld		de, path
		ld		a, 0x00			; オープンモード: 読み書き可
		ld		b, 0x00			; 属性: 通常ファイル
		ld		c, 0x44			; _CREATE
		call	BDOS
		or		a, a
		jp		nz, err_create
		ld		a, b
		ld		[handle], a		; ハンドルを保存
		; --- 書き込み ---
		ld		a, [handle]
		ld		b, a
		ld		de, text
		ld		hl, text_end - text
		ld		c, 0x49			; _WRITE
		call	BDOS
```

## 5.8 サンプル： シークと読み込み、エラー表示

hread.asm（◆）は、(1) 存在しないファイルを開いて _EXPLAIN の表示を試し、(2) HELLO.TXT を開いて 6 バイト進めてから残りを読み、(3) RESULT.TXT に書き出す、という 3 部構成のサンプルである。DOS2 環境で、RESULT.TXT が HELLO.TXT の 7 バイト目以降と一致すること、画面に「File not found」相当の説明文が出ることを確認した。

# 第6章 ディレクトリとパス ◆

## 6.1 FIB（ファイル情報ブロック） ◆

DOS2 の検索とメタ情報の受け渡しには、FIB（File Information Block、64 バイト）が使われる。FCB と違い、FIB は「開いたファイルの操作票」ではなく「ディレクトリエントリの写し」であり、名前は通常の文字列（ASCIIZ）で入る。

| オフセット | サイズ | 内容 |
|---|---:|---|
| +0 | 1 | シグネチャ（常に FFh） |
| +1 | 13 | ファイル名（"NAME.EXT" 形式の ASCIIZ） |
| +14 | 1 | 属性（b0 読取専用、b1 隠し、b2 システム、b3 ボリューム、b4 ディレクトリ、b5 アーカイブ、b7 デバイス） |
| +15 | 2 | 更新時刻 |
| +17 | 2 | 更新日付 |
| +19 | 2 | 先頭クラスタ |
| +21 | 4 | ファイルサイズ |
| +25 | 1 | 論理ドライブ番号 |
| +26 | 38 | 内部情報（変更してはならない） |

FIB は、_OPEN／_CREATE の対象指定（DE に FIB のアドレスを入れる）、検索結果の受け取り、_FNEW のテンプレート、など複数の場面で使い回される。内部情報の領域（+26 以降）は DOS が検索の継続などに使うため、プログラムが書き換えてはならない。

## 6.2 検索 _FFIRST／_FNEXT／_FNEW ◆

| 番号 | 名前 | 入力 | 出力 |
|---|---|---|---|
| 40h | _FFIRST | DE=パス名（ASCIIZ）、B=検索属性、IX=FIB 領域 | A=エラーコード、FIB に最初の一致エントリ |
| 41h | _FNEXT | IX=直前の FIB | A=エラーコード、FIB に次の一致エントリ |
| 42h | _FNEW | DE=パス名、B=作成属性＋b7=新規作成フラグ、IX=テンプレート FIB | A=エラーコード、FIB に新規エントリ |

検索属性（B）は「どの属性のエントリを対象にするか」の指定である。B=0 では、隠しでもシステムでもない通常ファイルだけが返る。ディレクトリも列挙したい場合は b4 を立てる。ボリュームラベル（b3）を指定した場合は排他的にラベルだけが検索される。

見つからなければ A=.NOFIL（ファイルなしエラー）である。_FNEXT は直前の _FFIRST／_FNEXT の続きであり、FIB の内部情報を DOS が使っているため、検索の途中で FIB を他の用途に使い回してはならない。

_FNEW は「なければ作る」検索で、ワイルドカードを含む名前に対して、まだ存在しない最初の名前を確定して長さ 0 のファイル（またはディレクトリ）を作る。連番ファイルの生成などに使われる古典的な仕掛けである。

## 6.3 サンプル： FIB による列挙

fflist.asm（◆）は、カレントディレクトリの全エントリ（ディレクトリを含む）を FIB で列挙し、名前を DIRH.TXT に書き出すサンプルである。FCB 版の dirlist.asm（4 章）と比べると、名前が "NAME.EXT" の完成形で返るため、空白パディングの整形が要らないことが分かる。DOS2 環境で、DIRH.TXT に MSXDOS2.SYS や COMMAND2.COM 等が並ぶことを確認した。

## 6.4 ディレクトリ操作 ◆

| 番号 | 名前 | 役割 |
|---|---|---|
| 4Dh | _DELETE | パス指定で削除 |
| 4Eh | _RENAME | パス指定で名前変更（HL=新ファイル名） |
| 4Fh | _MOVE | パス指定で移動（HL=新しいパス） |
| 50h | _ATTR | パス指定で属性の取得／設定（A=0 取得、1 設定、L=属性） |
| 51h | _FTIME | パス指定で日時の取得／設定 |

ディレクトリの作成は _CREATE（44h）にディレクトリ属性（b4）を指定して行い、削除は _DELETE で行う（対象が空でないディレクトリはエラーになる）。

ハンドル指定版（52h _HDELETE、53h _HRENAME、54h _HMOVE、55h _HATTR、56h _HFTIME）も用意されており、開いているファイルに対して操作できる。ハンドル版は暗黙に _ENSURE を伴う。削除（_HDELETE）の場合、エラー時でもハンドルは必ず閉じられること、別のオープンがあると .FOPEN エラーになることなど、共有の規則が細かく決まっている（第8章参照）。

## 6.5 カレントディレクトリとパス解析 ◆

| 番号 | 名前 | 役割 |
|---|---|---|
| 59h | _GETCD | カレントディレクトリの取得（DE=64 バイトバッファ）。ドライブ名や前後の '\' は含まず、ルートは空文字列 |
| 5Ah | _CHDIR | カレントディレクトリの変更（DE=パス名） |
| 5Bh | _PARSE | パス名の構文解析（ディスクアクセスなし）。最終要素の位置と論理ドライブ番号が返る |
| 5Ch | _PFILE | ファイル名を 8+3 の展開形（11 バイト）に変換。'*' は '?' 群に展開 |
| 5Dh | _CHKCHR | 1 文字のチェック： 大文字化と 2 バイト文字の判定 |
| 5Eh | _WPATH | 直前の検索結果に対するフルパス文字列の取得 |

_GETCD が返すパスに先頭の '\' が付かない点は、表示や連結の際に間違えやすい。envdemo.asm（7 章）では、表示用に自分で '\' を補っている。

_PARSE／_PFILE／_CHKCHR はディスクに触れない純粋な文字列処理であり、コマンドライン引数の解釈やワイルドカード処理を自前で書く際の部品になる。特に _CHKCHR は、2 バイト文字（漢字）の第 1 バイトを踏まないための判定を DOS 側の規則で行えるため、日本語ファイル名を扱うプログラムでは価値が高い。

# 第7章 環境・プロセス・システム ◆

## 7.1 環境アイテム ◆

環境アイテムは、DOS2 が保持する「名前＝値」の文字列の集合である。PATH、SHELL、TEMP といった標準アイテムを COMMAND2.COM が解釈して使うほか、アプリケーションが独自のアイテムを置いて、バッチファイルや他のプログラムと情報をやり取りできる。設計の要点は「保持はカーネル、解釈は利用者ごと」であり、DOS 自身は値の意味を知らない。

| 番号 | 名前 | 入力 | 出力 |
|---|---|---|---|
| 6Bh | _GENV | HL=アイテム名（ASCIIZ）、DE=値バッファ、B=バッファサイズ | A=エラーコード、バッファに値 |
| 6Ch | _SENV | HL=アイテム名、DE=値（ASCIIZ） | A=エラーコード |
| 6Dh | _FENV | DE=アイテム番号（1 から）、HL=名前バッファ | A=エラーコード、バッファにアイテム名 |

注意点：

- _GENV／_SENV は、他のファンクションとレジスタの役回りが違う（**名前が HL、値が DE**）。取り違えると、値の文字列がアイテム名として登録される、といった静かな誤動作になる。本書の envdemo.asm は、この点をコメントで強調した実例である。
- 存在しない名前を _GENV で読むと、エラーではなく空文字列が返る。
- _SENV で値を空文字列にすると、そのアイテムは削除される。
- _GENV のバッファが不足すると、終端の 0 なしで切り詰められ .ELONG エラーになる。255 バイト確保しておけば常に十分である。

## 7.2 プロセス ◆

| 番号 | 名前 | 役割 |
|---|---|---|
| 60h | _FORK | 子プロセスへ分岐する。戻り値 B は親プロセス ID。継承可ビット（オープンモード b2）付きのハンドルと標準ハンドルだけが子に引き継がれる |
| 61h | _JOIN | 親プロセスへ戻る。B に子の主エラーコード、C に副エラーコードが返る |
| 62h | _TERM | 終了コード（B）付きでプログラムを終了する。DOS2 では _TERM0 ではなくこちらが推奨される |

COMMAND2.COM が外部コマンドを実行する際の実体が _FORK／_JOIN であり、終了コードは _TERM の B が源になっている。終了コードが 20h〜FFh の範囲だと、COMMAND2.COM は対応するエラーメッセージを表示する。

## 7.3 エラー処理のカスタマイズ ◆

| 番号 | 名前 | 役割 |
|---|---|---|
| 63h | _DEFAB | プログラム終了時（アボート時）に呼ばれるルーチンを登録する |
| 64h | _DEFER | ディスクエラー発生時に呼ばれるルーチンを登録する（Abort／Retry／Ignore の判断を自前で行う） |
| 65h | _ERROR | 直前のファンクションコールのエラーコードを取得する。主に DOS1 互換ファンクション（A=FFh 方式）の失敗理由を知るために使う |
| 66h | _EXPLAIN | エラーコードを説明文字列に変換する（5.6 節） |

_DEFER のルーチンには、エラーコード（A）、物理ドライブ（B）、状況フラグ（C）、セクタ番号（DE）が渡され、戻り値 A で システム既定処理／Abort／Retry／Ignore を指示する。エラールーチンの中で呼べるファンクションは制限される（再帰防止）ため、仕様書の指定を必ず確認すること。

_DEFAB と _DEFER は 0005h 経由でのみ登録できる（0F37Dh 経由では使えない）という違いもある。

## 7.4 システム管理 ◆

| 番号 | 名前 | 役割 |
|---|---|---|
| 67h | _FORMAT | ディスクのフォーマット（主に FORMAT コマンド用） |
| 68h | _RAMD | RAM ディスク（H:）の作成／削除／サイズ問い合わせ |
| 69h | _BUFFER | セクタバッファ数の取得／設定 |
| 6Ah | _ASSIGN | 論理ドライブと物理ドライブの割り当て変更 |
| 6Eh | _DSKCHK | ディスクチェック（アクセスごとのブートセクタ再確認）の有効／無効 |
| 6Fh | _DOSVER | カーネルと MSXDOS2.SYS のバージョン取得（1.5 節） |
| 70h | _REDIR | 標準入出力のリダイレクト状態の取得／設定 |

これらは主にシステムユーティリティ向けであり、通常のアプリケーションが触る機会は少ない。ただし _DOSVER だけは両対応プログラムの判別（1.5 節）で必須である。

## 7.5 日時とベリファイ ●

日時のファンクションは DOS1／DOS2 共通である。

| 番号 | 名前 | 入力／出力 |
|---|---|---|
| 2Ah | _GDATE | HL=年（1980〜2079）、D=月、E=日、A=曜日（0=日曜） |
| 2Bh | _SDATE | 同上を設定 |
| 2Ch | _GTIME | H=時、L=分、D=秒、E=1/100 秒 |
| 2Dh | _STIME | 同上を設定 |
| 2Eh | _VERIFY | E=FFh で書き込みベリファイ有効、00h で無効 |
| 58h | _GETVFY ◆ | 現在のベリファイ設定を B に返す |

DOS2 のファイル日時（_FTIME、FIB の時刻・日付フィールド）も同じビット形式であり、時刻は「時×2048＋分×32＋秒÷2」、日付は「（年−1980）×512＋月×32＋日」にパックされている。

## 7.6 サンプル： バージョン・現在地・環境

envdemo.asm（◆）は、_DOSVER でバージョン、_GETCD でカレントディレクトリ、_SENV／_GENV で環境アイテム PGDEMO の設定と読み戻しを行い、結果を RESULT.TXT に書き出すサンプルである。本書の検証環境（MSX-DOS2 系カーネル）での実行結果は次のとおり（実測）。

```
DOSVER=02.30
CD=\
PGDEMO=ON
```

1 行目のバージョンは環境のカーネルが返した値そのものである。純正の MSX-DOS2（version 2.20）では 02.20 になる。プログラムは戻り値を決め打ちせず、このように表示・判定に使うのが正しい。

_GETCD は先頭の '\' を返さないため、2 行目はサンプル側で '\' を補った表示である（6.5 節）。

# 第8章 ファンクションコールリファレンス

本章は全ファンクションの一覧です。記号の意味は第1章の凡例（●＝共通、◆＝DOS2 専用、▲＝共通だが差異あり）に従います。入力欄の「C＝番号」は全ファンクション共通のため省略しています。出力は特記なき限り成功時の値です。40h 未満のファンクションは A にフラグ（00h 成功／FFh または 01h 失敗）を返し、40h 以上は A にエラーコード（00h＝エラーなし）を返します（第1章）。

収録範囲は、DOS1 の 42 機能（●・▲）と DOS2 で新設された 50 機能（◆）の、合計 92 機能です。00h〜70h のうち 21 番号は未使用です（8.11節）。

# 付録A エラーコード一覧 ◆

DOS2 のエラーコードの一覧です（ASCII MSX-DOS 2 Program Interface Specification §6）。コードは FFh から降順に割り当てられ、40h〜FFh がシステムエラー、00h〜3Fh はユーザーエラー用に予約されています（システムは使いません）。40h 以上のファンクションは A にこのコードを返し、40h 未満のファンクションの失敗理由は _ERROR（65h）でこのコードとして取得できます。コードから説明文字列を得るには _EXPLAIN（66h）を使います。

## A.1 ディスクエラー

ディスクエラールーチン（_DEFER）に渡される系統のエラーです。

| コード | 名前 | 意味 |
|---:|---|---|
| FFh | .INCOMP | 互換性のないディスク |

# 付録B サンプルプログラム一覧と検証結果

本書のサンプルはすべて zma（Z80／R800 マクロアセンブラ）で書かれており、クロス版 zma でアセンブルできることを確認しています。また主要なサンプルは、openMSX のフォーク（V9968 対応版、Panasonic FS-A1ST 構成）上の MSX-DOS 環境と MSX-DOS2 環境で実際に動作させ、作成されたファイルの内容まで照合しました。本付録に、その一覧と検証結果をまとめます。サンプルのソースと実行ファイルは、別途サンプル集（zip）として配布しています。

## B.1 サンプル一覧

| ファイル | 記号 | 内容 | 主なファンクション | 掲載 |
|---|---|---|---|---|
| hello.asm | ● | "Hello, MSX-DOS!" と表示して終了 | _STROUT、_TERM／_TERM0 | 第1章 |

## B.2 検証方法

- アセンブル： クロス版 zma で全 11 本が "Success." となることを確認。実行ファイルのサイズは hello 25 バイト、conio 178 バイト、fcbmake 454 バイト、fcbcopy 502 バイト、fcbrand 368 バイト、dirlist 4,626 バイト、alloc 206 バイト、hmake 298 バイト、hread 759 バイト、fflist 4,380 バイト、envdemo 987 バイト。
- 動作確認： 各サンプルをシステムディスクのイメージに加え、AUTOEXEC.BAT から起動する方式で実行（conio のみ対話操作で実行）。実行後にディスクイメージからファイルを抽出し、内容をバイト単位で照合した。
- DOS1 環境は MSX-DOS（MSXDOS.SYS version 1.03 系）のディスク、DOS2 環境は MSX-DOS2 系カーネルのディスクを使用した。DOS2 環境の _DOSVER は 02.30 を返した（検証環境のカーネルによる。純正 MSX-DOS2 2.20 では 02.20 になる）。

## B.3 検証結果

| サンプル | DOS2 | DOS1 | 照合内容 |
|---|---|---|---|
| hello | 確認 | 確認 | 画面表示 |
| conio | 確認（対話） | ― | プロンプトから起動し、入力した行がそのまま表示されることを確認。使うファンクションはすべて共通 |

| fcbcopy | 確認 | 確認 | COPY.TXT が TEST1.TXT とバイト単位で一致 |
| fcbrand | 確認 | 確認 | RAND.BIN が 64 バイト（16 バイト×4 レコード）で、レコード 2 の読み戻し結果 RESULT.TXT（16 バイト）が一致 |
| dirlist | 確認 | 確認 | DIR.TXT に全ファイルが "名前.拡張子" 形式で列挙されることを確認 |
